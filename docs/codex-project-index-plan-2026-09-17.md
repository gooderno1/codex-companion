# Codex 项目归因与详情查询索引

- 基线：v0.6.0；实施：v0.6.1-dev.1；用户已明确项目应对应 Codex 项目、Git 只是可选关联。
- 根因：详情按仓库建项目列表，没有数据库；首次全量解析后同步等待 collectGitData 的多周期 Git 统计，切日期还会重新读取所有仓库历史。
- 权威来源：只读 Codex state SQLite 的 projects / project_roots / threads.project_id，以及 .codex-global-state.json 的 local-projects / 显式归属 / 项目迁移映射；不读取会话正文或凭据。
- 归因优先级：明确的数据库归属、桌面端显式归属、明确无项目、旧版 root hint、cwd 最长根路径匹配。保留无 Git 项目；未匹配记录单列“无项目 / 未匹配”，不能按 Git 创建假项目。
- 当前项目名称和根目录跟随 Codex；不同项目即使关联同一仓库也保持独立。工作树优先使用显式归属，不靠目录同名猜测。
- 总览项目表、会话归因和历史详情使用同一映射。代码仓库页仍是独立 Git 视图；无 Git 的代码指标显示不适用。
- 自建 SQLite 仅放在 Companion 用户数据目录；记录文件 size / mtime、会话元数据、结构化 Token 事件和时间索引。按文件增量替换、删除消失文件、事务更新，索引可重建；不改写 Codex 数据库。
- 查询按时间索引选择事件，原文件未变化不重新解析；重启也复用索引，更新定价时按索引版本重建。统计仍调用现有解析逻辑，未改 Token / reset 算法；远程核心已核对仍为 v0.2.0-dev.3。
- Git 只在选中项目并点击加载时查询，单独缓存；不阻塞项目或会话用量列表，无 Git 显示未关联。
- 验证：有 / 无 Git 项目、嵌套根、重命名、工作树显式归属、无项目优先级、旧版兼容；冷启动 / 重启 / 范围切换耗时及增量解析计数；数据库时间索引查询计划；真实 Electron 验证。

## 实施结果

- 创建日期：2026-09-17；状态：v0.6.1-dev.1 已实现并验证。
- 映射：`codexProjects.ts` 统一真实项目身份；相同根目录的歧义、显式关联已删除项目不猜测，旧版保存的工作目录也能回退。
- 索引：`state/activityIndex.ts` 使用文件主键、事件时间索引、WAL 和可重建缓存的 NORMAL 同步级别；索引版本关联现有解析缓存版本。原始数据解析和核心依赖未改。
- 页面：总览及会话归因使用同一项目清单；Git 指标为可选项，详情独立按需查询。旧版项目快照以 `projectAttributionVersion=1` 迁移。
- 本机基准：旧版全历史首次 31.134 秒；新版 526 个文件首次建立索引 25.185 秒（复用普通缓存 74 个文件，解析 452 个）。
- 本机基准：近 7 天 0.216 秒；全部历史 0.823 秒；关闭数据库后重新创建服务 0.838 秒，全部 526 个文件复用。覆盖 493 条有用量的会话、30 个 Codex 项目和一个无项目分组。
- 性能边界：首次必须处理本机保留历史，仍需等待；上述性能来自该次本机测试，并非所有设备承诺。常规仪表盘的 Git 仓库刷新保留既有路径，不计入详情查询时间。
- 验证：完整构建、`verify:activity`（含项目 / SQLite 专项）、`verify:usage`、`verify:comparisons`、`verify:ledger`；SQLite 查询计划命中 `events_at`。
- 验证：真实 Electron 双入口、非 Git 项目、按需 Git、历史日期、分页、搜索、窄窗口与关闭 / 焦点恢复。截图及真实数据基准留在忽略目录 `local_dev_work/`。
