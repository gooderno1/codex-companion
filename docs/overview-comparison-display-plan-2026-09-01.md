# 总览变化值显示切换规划（2026-09-01）

- 创建时间：`2026-09-01 18:13:40 +08:00`
- 创建时版本基线：`v0.5.1`，main `a439c24`
- 计划开发版本：`v0.5.2-dev.1`
- 需求主题：零分母按 `1` 计算百分比，并支持在百分比与绝对变化量之间切换
- 影响页面：总览页顶部工具栏、顶部四张指标卡
- 当前阶段：`v0.5.2-dev.1` 已完成实现与验收，正在发布 `v0.5.2`

## 1. 当前问题

`v0.5.1` 已把变化值改为上一周期同期，但当前 `describeDelta()` 在上一周期同期为 `0`、当前大于 `0` 时显示“新增”，不显示具体百分比。

当前 live 样例：

- 本月 Token：当前 `125,778,327`，上月同期 `0`。
- 今日代码改动：当前 `6,541 行`，昨日同期 `0`。

用户确认的新规则是：参与百分比计算的基准数为 `0` 时，按 `1` 作为分母。同时需要一个全局切换，在“百分比”和“绝对数值”之间切换顶部四卡的变化说明。

## 2. 百分比口径

推荐把“0 按 1 计算”严格限定为分母替换，当前值和上一周期真实值不改写：

```text
effectivePrevious = previous === 0 ? 1 : abs(previous)
deltaPercent = (current - previous) / effectivePrevious * 100
```

示例：

| 当前值 | 上期同期 | 百分比结果 | 说明 |
| ---: | ---: | ---: | --- |
| `150` | `100` | `+50.0%` | 普通增长 |
| `50` | `100` | `-50.0%` | 普通下降 |
| `0` | `100` | `-100.0%` | 当前归零 |
| `0` | `0` | `0.0%` | 两期均为零 |
| `6,541` | `0` | `+654,100.0%` | 分母按 `1` |
| `125,778,327` | `0` | `+12,577,832,700.0%` | 分母按 `1` |

注意：最后两类百分比会非常大，这是规则本身的直接结果，不再使用“新增”替代。

## 3. 超大百分比格式

顶部卡片宽度有限，推荐采用“卡片紧凑显示 + 完整数值提示”的两层格式：

- 小于 `10,000%`：保留一位小数并使用千分位，例如 `+4,123.4%`。
- 大于等于 `10,000%`：使用中文紧凑单位，例如 `+65.4万%`、`+125.8亿%`。
- 卡片元素的 `title` 与无障碍标签保留完整值，例如 `+12,577,832,700.0%`。
- 不使用科学计数法，不截断正负号和百分号。

这样能遵守“0 按 1 计算”，同时避免超长百分比挤压四卡布局。

## 4. 绝对数值口径

绝对数值模式使用真实值直接相减，不应用“0 按 1”规则：

```text
deltaAbsolute = current - previous
```

显示规则：

- Token：`较上月同期 +1.3 亿 tok`、`较昨日同期 -3,200 tok`。
- 代码：`较昨日同期 +6,541 行`、`较昨日同期 -420 行`。
- 差值为 `0`：显示 `较上期同期 持平`，不显示正负号。
- 卡片使用现有紧凑数字规则，悬停提示提供完整差值。

主数字仍显示当前周期值；切换只改变卡片第三行的变化说明，不修改总量、周期边界或数据采集。

## 5. 切换位置

推荐放在总览页顶部工具栏中部，与现有“时间视角”并列，形成两个同层级的视图控制：

```text
时间视角  自然时间  计费时间   |   变化显示  百分比  数值
```

选择该位置的原因：

- 它是作用于四张指标卡的全局展示偏好，不属于任何单张卡片。
- 不新增顶部四卡上方的独立行，不压缩额度卡和项目概览高度。
- 与“自然时间 / 计费时间”一样，只改变观察方式，不改变底层数据。
- 现有页面在 `1160px` 以下会整体缩放，在窄于 `980px` 时顶栏改为纵向，因此可继续使用同一响应式结构。

备选位置是在顶部四卡上方增加“变化显示”工具行，但会永久增加页面高度，当前不推荐。

## 6. 默认值与持久化

推荐：

- 默认模式：`百分比`，保持现有主要阅读方式。
- 用户切换后写入本机 `AppPreferences.overview.comparisonDisplay`，取值为 `percentage / absolute`。
- 旧版 `settings.json` 缺字段时自动迁移为 `percentage`。
- 设置只保存在 Electron `userData/settings.json`，不上传，不触发 Codex / Git 数据重新采集。
- 顶部工具栏是唯一操作入口，设置页暂不重复增加同一选项。

如果不要求跨重启记忆，可以只保留 renderer 会话状态；但这会让用户每次启动都重新切换，体验较弱，不作为推荐方案。

## 7. 数据源与不变项

继续使用现有字段：

- 当前值：`overview.today / naturalWeek / month / windowPeriods.weekLimit / windowPeriods.billingMonth`。
- 上一周期同期：`overview.previous.yesterday / naturalWeek / month / weekLimit / billingMonth`。

本次不修改：

- Codex session 解析和 token 增量。
- `rate_limits`、额度周期、reset 检测和 `quotaEvidence`。
- `@lifeinhand/codex-usage-core` 版本。
- 当前值和上一周期同期的时间边界。
- 额度圆环、账本页和代码仓库页。
