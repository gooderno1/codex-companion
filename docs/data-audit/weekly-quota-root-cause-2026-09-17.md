# 周额度余量根因与修复验收

- 创建时间：2026-09-17。
- 基线：Companion `0.5.3-dev.1`，核心包 `0.2.0-dev.1`（远端 HEAD `644691e`）。
- 用户确认：圆环和低额度提醒采用官方当前余量；失败时使用本地最新有效窗口。历史累计消耗保留用于账本和价值估算。
- 范围：共享核心包、Companion 采集和缓存、额度卡、通知、挂件、验证脚本；同步核心包的另一个下游 dev-ledger。

## 根因

1. `observedAt` 是记录写入时间，不是额度窗口身份。并行会话可以在新窗口开始后写入旧窗口观测。
2. 当前显示和历史累计混用：`buildDisplayedQuotaWindow` 用历史最高消耗覆盖官方快照；通知再次优先读取历史累计余量。
3. `dev.1` 仅在 reset 已确认后迁移旧观测。30 分钟确认前、缺少确认样本时仍可能污染当前值。
4. 核心包确认阶段把旧窗口延迟样本当作新窗口漂移；后续真实 reset 也可能否定前一个 reset，12 小时去重还可能合并不同窗口。
5. 本地回退只比较写入时间，可能倒退到已被新窗口取代的旧窗口；过期窗口也可能继续显示。
6. 启动缓存与通知必须共同迁移，否则新计算生效前仍会显示旧语义快照。

## 实施顺序

1. 用脱敏 fixture 复现确认前、旧窗口延迟、连续 reset、乱序、过期和无效字段。
2. 核心包提供当前窗口校验、旧窗口淘汰和观测周期归属；修正 reset 确认与去重。
3. Companion 仅负责映射；官方当前值不依赖历史 reset 是否确认，历史证据不覆盖当前值。
4. 统一通知、挂件、快照缓存版本和数据源文案；更新验收规则。
5. 发布核心包远程 tag，升级两个下游；构建、真实数据采集、页面检查、安装包和 Git 同步。

## 验收不变量

- 官方 `usedPercent=51` 时当前余量必须为 `49`，即使历史高水位为 `98` 或 reset 尚未确认。
- 当前截止时间来自当前窗口；过期或无效回退数据不伪装成当前可用额度。
- 同一窗口当前值回落只改变当前余量，历史高水位仍保留。
- 旧窗口迟到不得倒退当前窗口，也不得让已稳定的新窗口失去 reset 确认。
- 不同额度池、不同窗口时长隔离；乱序输入结果确定；Token 按真实时间归属。
- 不从缺失数据推算余量或伪造 reset；未知状态必须明确显示。
