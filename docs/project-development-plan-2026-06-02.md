## 1. 产品定位

Codex Companion 是面向 Codex 重度用户的非官方开源桌面伴侣。它不替代 Codex，也不做通用 AI 编程工具面板，而是专注展示 Codex 使用过程中的额度、Token、成本价值和代码产出。

首版目标：

- 无需登录即可在本机运行。
- 自动读取本机 Codex 使用数据。
- 展示今日、近 7 日、本月 Token 和代码改动。
- 按 Codex 计费窗口展示 5 小时、周和可观测月周期。
- 估算 API 等价成本和套餐额度价值。
- 通过桌面挂件常驻展示最关键的 Codex 信号。

非目标：

- 首版不接入 Claude Code、Cursor、GitHub Copilot 等其他 provider。
- 首版不做团队管理、云端同步或 SaaS 后台。
- 首版不做完整 GitHub 客户端，只把 Git 仓库统计作为 Codex 投入归因的一部分。
- 首版不上传原始 Codex session 文件。

## 3. 产品信息架构

### 3.1 总览页

总览页用于快速判断今天和最近周期的 Codex 使用是否正常。

核心指标：

- 今日 Codex Token
- 近 7 日 Codex Token
- 本月 Codex Token
- 今日代码改动行数
- 近 7 日代码改动行数
- 本月代码改动行数
- 当前 5 小时额度余量
- 当前周额度余量
- 本周 API 等价成本
- 本周套餐价值折算
- 最近刷新状态和数据可信度

页面约束：

- 首屏不放长列表。
- 所有额度字段必须显示来源状态：`已观测`、`未观测`、`待刷新` 或 `数据过期`。
- 成本和价值折算只作为摘要，不在总览页展开完整模型细账。
- 页面内不出现 Claude Code、Cursor、Copilot 等 provider 入口。

### 3.2 Codex 账本页

Codex 账本页是项目核心页面，用于查看额度周期、使用量、成本和价值。

统计维度：

- 自然时间：今日、本周、本月。
- 计费时间：5 小时窗口、周计费周期、可观测月计费周期。
- 额度状态：已用百分比、剩余百分比、恢复时间、周期起止。
- 使用量：Token、会话数、模型构成、缓存输入 / 普通输入 / 输出 Token。
- 成本：API 等价成本估算、已定价覆盖、未定价 Token。
- 价值：套餐额度 API 等价价值折算、满额估值、模型构成来源。

页面结构：

1. 当前额度：5 小时 / 周 / 月三个周期，月周期未观测时明确标记。
2. 周期账本：按计费周期展示 Token、额度百分比、成本和价值。
3. 模型构成：按 Token、成本、调用次数切换。
4. 会话归因：按项目 / 仓库展示 Codex 投入。
5. 数据说明：只在必要处显示来源标签，不堆解释性长文案。

### 3.3 代码仓库页

代码仓库页用于回答 Codex 投入和本地代码产出的关系。

首版展示：

- 本地仓库列表
- 仓库路径、远端 URL、默认分支
- 今日 / 7 日 / 本月提交数
- 今日 / 7 日 / 本月代码改动行数
- 新增 / 删除 / 净变化
- 活跃仓库排行
- Codex Token 归因到仓库后的投入排行
- 单仓库详情：近期提交、语言或文件体量概览、Codex 投入、代码改动趋势

后续可选能力：

- GitHub 仓库元数据
- PR / Issue 活跃度
- Stars / forks / releases
- GitHub Actions 状态
- 多设备同仓库归并

## 4. 桌面挂件规划

### 4.1 顶部 Codex 信号条

首版默认挂件采用桌面中间靠上的横向信号条。

推荐尺寸：

- 桌面端默认：`720px x 108px`
- 宽屏上限：`860px x 118px`
- 小屏下限：`560px x 96px`

默认展示：

- 今日 Token
- 套餐剩余
- 本周 Token
- 本月 Token

视觉结构：

- 浅蓝半透明胶囊条，细边框，小圆角，不做厚重卡片。
- 左侧显示 `Codex 伴侣 · 正常`。
- 中间四个等宽指标块，数字为主，标签为辅。
- 每个指标块底部可放迷你柱图或细进度线。
- `套餐剩余` 使用水平进度或环形比例表达百分比。
- 右侧放刷新时间和设置图标，鼠标移入时显示完整控制。

### 4.2 挂件预设

| 预设 | 位置 | 尺寸倾向 | 展示内容 | 使用场景 |
| --- | --- | --- | --- | --- |
| 顶部 Codex 信号条 | 顶部中间 | 宽而低 | 今日 Token、套餐剩余、本周 Token、本月 Token | 默认推荐，编码时低打扰。 |
| Codex 极简胶囊 | 任意边缘 | 很小 | 今日 Token、剩余额度、状态点 | 录屏、会议、专注模式。 |
| Codex 四宫格 | 桌面右上或副屏 | 中等面板 | Token、成本、代码、状态 | 副屏常驻。 |
| Codex 预算雷达 | 右侧窄栏 | 竖向 | 周额度、成本、模型排行、提醒 | 预算敏感用户。 |

第一阶段优先级：

1. 顶部 Codex 信号条。
2. Codex 极简胶囊。
3. Codex 四宫格。
4. Codex 预算雷达。

### 4.3 挂件交互

- 默认不抢焦点，不遮挡应用操作。
- 支持拖动、锁定位置、点击穿透、透明度、隐私模式。
- 点击指标可打开桌面应用对应页面。
- 支持普通窗口层和桌面贴附层两种模式。
- 数据过期、额度不足、采集错误时，用颜色和描边提醒，不默认弹系统通知。

## 6. 数据与技术架构

### 6.1 首版单机架构

推荐模块：

- `desktop-shell`：桌面窗口、托盘、挂件窗口、系统权限。
- `codex-collector`：Codex session、额度快照、计费周期和模型成本采集。
- `git-collector`：本地 Git 仓库和代码改动采集。
- `ledger-store`：本地 SQLite 或 JSON 快照存储。
- `ui-web`：桌面应用前端页面。
- `widget-ui`：桌面挂件渲染层。
- `codex-contract`：统一 Codex Token、额度、成本、价值和代码归因字段。

存储建议：

- `v0.1` 可以先使用 JSON 快照，便于快速从 DevLedger 抽取可运行能力。
- 若要长期维护历史周期、增量采集和后续云同步，应尽早设计 SQLite schema。
- 折中路线：先保留 JSON 输出，同时在文档中稳定数据契约；`v0.2` 再迁移到 SQLite 主存储。

### 6.2 数据模块

Codex 数据模块：

- 读取 Codex 本地 session 和 archived session。
- 解析 `token_count`、`turn_context.model`、`rate_limits` 等字段。
- 支持自然日、自然周、自然月。
- 支持 5 小时窗口、周计费周期和可观测月计费周期。
- `5 小时额度` 周期内经历 reset 时按分段高点累计真实额度使用百分比。
- `周额度` 经稳定确认的 reset 应作为新计费周边界，旧周期提前截止，新周期从重置后的窗口起点开始。
- API 等价成本必须区分普通输入、缓存输入和输出 Token。

Git 数据模块：

- 扫描用户配置的本地仓库根目录。
- 聚合提交数、改动行数、新增、删除和仓库活跃度。
- 通过工作目录、远端 URL 或项目路径把 Codex session 归因到仓库。
- 首版不要求 GitHub token。

GitHub 数据模块：

- 后续登录或授权阶段接入。
- 主要补远端仓库、PR、Issue 和 Actions 状态。
- 不改变 Codex 专用主线。

## 7. 技术路线

首选路线：

- 桌面壳：Electron，优先复用 DevLedger 已验证过的 Windows 挂件经验。
- 前端：先使用轻量 Web 技术，后续根据复杂度再决定是否引入 React / Vite。
- 数据层：先 JSON 快照，后续 SQLite。
- 构建：首版先建立稳定的 `npm run build`，后续补安装包构建。

备选路线：

- Tauri 可以降低体积和资源占用，但首版会增加 Rust / WebView / Windows 窗口能力验证成本。
- 如果第一阶段优先速度和迁移 DevLedger 能力，Electron 更务实。

## 8. 桌面应用还是 Codex 插件

结论：主产品做桌面应用，Codex 插件作为后续伴随扩展。

原因：

- 项目核心需要常驻桌面窗口、托盘、挂件、后台采集、本地存储、计费周期归档和后续账号同步。
- 这些能力更符合桌面应用边界。
- Codex 插件适合帮助用户在 Codex 内初始化配置、读取本地统计摘要、生成周报、解释额度异常或连接本地 MCP。
- 不应把 Codex 插件作为唯一入口，否则离开 Codex 后无法继续使用挂件和统计。

推荐路线：

1. 先做 `Codex Companion Desktop`，确保单机可用。
2. 后续补 `Codex Companion Plugin`。
3. 插件通过 MCP 或本地 HTTP 读取桌面应用摘要。

## 9. 隐私与同步

首版不做登录。

首版隐私原则：

- 默认 local-first。
- 不上传原始 Codex session。
- 不上传仓库名、路径、模型明细或成本数据。
- 对外文档明确说明采集路径和字段。

后续账号体系目标：

- 同一用户多台设备 Codex 使用数据同步。
- 不同账户或 workspace 数据可分开统计。
- 可选择是否上传敏感仓库名、模型明细和成本数据。
- 云端只保存聚合数据，原始 Codex session 文件默认不上传。

阶段设计：

1. 本地账户：仅用于区分不同本机 profile。
2. 云端登录：同步聚合快照、配置和挂件布局。
3. 团队空间：多成员共享 Codex 额度、成本和代码活动视图。

## 12. 本轮实施结果（v0.2.0-dev.1）

已落地内容：

- 确认首版桌面壳继续采用 Electron。
- 采用 `React + TypeScript + Vite` 作为界面层。
- 首版存储采用本地 JSON 快照。
- GitHub 远端数据继续留在后续阶段，不进入本轮首个公开版本。
- 桌面挂件默认采用顶部中间的 `Codex 信号条`，同时补充 `Codex 极简胶囊` 预设。
- 完成总览页、Codex 账本页、代码仓库页和桌面挂件。
- 完成本机 Codex session、`rate_limits` 和本地 Git 仓库采集。
- 完成构建命令、隐私说明、路线图、贡献说明、Issue 模板和数据契约文档。

当前保留项：

- 月额度仍取决于本地 `rate_limits` 是否暴露月字段；当前保持 `未观测` 兜底。
- SQLite 历史存储、云端同步和 GitHub 元数据仍按后续阶段推进。
