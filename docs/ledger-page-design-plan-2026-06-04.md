## 模块级细化结论

### 1. 时间范围不再挂在页面最上方

- `日 / 周 / 月` 只影响：
  - `Token 走势拆解`
- 它不影响：
  - `周期洞察`
  - `模型贡献`
  - `周额度账本`
  - `会话归因`
- 因此 `日 / 周 / 月` 必须从页面顶部工具栏移入 `Token 走势拆解` 模块头部，作为该分析模块的局部状态，而不是整页状态。

### 1.1 右侧两个模块的周期单独定义

- `周期洞察` 与 `模型贡献` 都在模块右上角单独放周期切换。
- 统一用：
  - `近7天`
  - `近30天`
  - `累计`
- 不用：
  - `周 / 月 / 全部`

选择理由：

- `周 / 月` 很容易被理解成自然周 / 自然月，但这里实际是滚动窗口。
- `全部` 边界不清，不知道是全部会话、全部分页，还是全部观测期。
- `累计` 更明确，它表达的是“从本地首个可观测事件到当前快照”的累计观察期。

### 2. 时间范围建议定义

- `日`：当前自然日 `00:00` 到快照时刻，按小时分桶。
- `周`：最近 `7` 个自然日，按日期分桶。
- `月`：最近 `30` 个自然日。
  - 默认按日期分桶。
  - 允许切到 `周段`，把最近 `30` 天压成 `5` 个连续周段。

选择理由：

- 第二页要回答的是“最近强度如何变化”，不是日历页，也不是计费窗口页。
- `周额度账本` 已经承担了计费周期表达，因此强度图不再复用 `5H / 周额度 / 月额度` 的窗口语义。

### 3. Token 关系必须先讲清

- `总 Token = 输入总量 + 输出`
- `输入总量 = 原始输入 + 缓存输入`
- `缓存输入占比 = 缓存输入 / 输入总量`
- `推理 Token <= 输出`
- 当前 `reasoningOutput` 应视为 `output` 的子集，而不是独立第四段。
- 当前 `input` 应视为“输入总量”，其中已经包含缓存命中的那一部分；前端若要做堆叠图，必须先推导：
  - `原始输入 = max(0, input - cachedInput)`

### 4. 横轴与纵轴的最终可选项

- 一级时间范围：
  - `日`
  - `周`
  - `月`
- 横轴：
  - `日`：固定 `小时`
  - `周`：固定 `日期`
  - `月`：`日期` / `周段`
- 纵轴：
  - `总 Token`
  - `输入总量`
  - `缓存输入`
  - `缓存输入占比`
  - `输出`
  - `推理 Token`

说明：

- `日` 和 `周` 没有第二种横轴时，不显示横轴切换控件。
- 纵轴名建议写成 `输入总量`，不要只写 `输入`，否则用户容易误解为“未命中缓存的原始输入”。

### 5. 柱形图不采用“四段并列堆叠”

- `总 Token`：
  - 主柱采用 `原始输入 + 缓存输入 + 输出` 三段堆叠。
  - `推理 Token` 不单独再占一段，而是在 `输出` 段内部用深色内嵌层或 hatch 标记它所占子集。
- `输入总量`：
  - 采用 `原始输入 + 缓存输入` 两段堆叠。
- `缓存输入`：
  - 单序列柱图。
- `缓存输入占比`：
  - 百分比柱图，不再叠加任何绝对量。
- `输出`：
  - 单序列柱图；如果需要强调推理占比，在柱内标记推理子集。
- `推理 Token`：
  - 单序列柱图。

### 6. 纵轴规则

- 默认只保留左侧纵轴。
- 右侧纵轴默认不显示。
- 如果设计上希望保留右侧刻度，只允许做左轴镜像，不允许拿来表达第二种单位。
- `缓存输入占比` 纵轴固定为 `0% - 100%`。
- 绝对量纵轴按当前窗口最大值自动取整到友好刻度，例如 `5000万 / 1亿 / 1.5亿`。

### 7. Hover / Tooltip 必须展示什么

- 鼠标悬停任一柱时，tooltip 统一展示：
  - 完整时间范围
  - 当前主指标值
  - `总 Token`
  - `输入总量`
  - `原始输入`
  - `缓存输入`
  - `缓存输入占比`
  - `输出`
  - `推理 Token`
  - `会话数`
  - `API 等价成本`
- 如果当前横轴为 `周段`，tooltip 还要展开该周段覆盖的起止日期。

### 8. 周期洞察建议固定口径，不跟纵轴漂移

- `周期洞察` 只跟随自己的 `近7天 / 近30天 / 累计` 时间范围。
- `周期洞察` 不跟随纵轴切换。
- 原因：
  - 如果摘要随纵轴一起漂移，用户一切到 `缓存输入占比` 或 `推理 Token`，六张摘要卡的含义就会整体变化，页面稳定性会很差。
  - 第二页需要一组稳定的“总量强度参考”，图形才负责做更细的指标探索。

建议固定 6 张摘要卡：

- `窗口累计`
- `窗口均值`
- `峰值位置`
- `峰值用量`
- `单次峰值`
- `缓存输入占比`

### 9. 周期洞察计算口径

- `窗口累计`
  - `近7天`：最近 `7` 日累计 `total`
  - `近30天`：最近 `30` 日累计 `total`
  - `累计`：观测期累计 `total`
- `窗口均值`
  - `近7天`：最近 `7` 日平均每日 `total`
  - `近30天`：最近 `30` 日平均每日 `total`
  - `累计`：观测期平均每日 `total`
- `峰值位置`
  - `近7天`：Token 最高的日期，例如 `06/02`
  - `近30天`：Token 最高的日期
  - `累计`：观测期内 Token 最高的日期
- `峰值用量`
  - 与 `峰值位置` 对应桶的 `total`
- `单次峰值`
  - 当前时间范围内，单个会话 `total` 最大值
- `缓存输入占比`
  - 当前时间范围内 `ΣcachedInput / Σinput`

### 10. 当前第二页示意图仍然是阶段图

- 新的 [ledger-page.png](./assets/design/v0.3.15/ledger-page.png) 已把当前模块合同落到图面。
- 这张图不再把 `日 / 周 / 月` 放在页面顶栏，也不再给 `模型贡献` 额外放排序按钮。
- 这张图已经同步：
  - `Token 构成与强度` -> `Token 走势拆解`
  - `强度摘要` -> `周期洞察`
  - `模型构成` -> `模型贡献`
  - `周期洞察 / 模型贡献` 右上角补 `近7天 / 近30天 / 累计`
