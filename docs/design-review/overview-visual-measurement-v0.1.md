# 总览页视觉比例测量（v0.1）

- 创建时间：2026-06-04
- 适用版本：`v0.2.2-dev.27`
- 设计基准：`docs/assets/design/v0.3.3/overview-natural-time.png`
- 实现截图：`local_dev_work/overview-1360x900-dev25.png`、`local_dev_work/overview-1080x720-dev25.png`
- 目的：把“对照设计稿还有差距”转成可复用的区块比例验收规则，避免后续页面只靠整页截图主观判断。

## 1. 测量方法

本文件采用轻量人工标注方式：

- 先读取图片实际像素尺寸。
- 再按视觉边界估算主要区块位置。
- 只比较比例和层级，不把 AI 设计图当作像素级切图规范。
- 对真实数据导致的数字长度、模型名长度、项目数量差异不做强行一致要求。

图片尺寸：

| 图像 | 尺寸 |
| --- | --- |
| 设计稿 `overview-natural-time.png` | `1536 x 1024` |
| 实现 `overview-1360x900-dev25.png` | `1683 x 1079` |
| 实现 `overview-1080x720-dev25.png` | `1333 x 854` |

## 4. 当前优先级判断

已达标：

- 左侧边栏宽度和品牌区层级。
- 顶部工具栏单行结构。
- 额度卡高度比例和真实数据说明。
- 小窗口完整显示。

仍可继续精修：

- 顶部四卡高度略低于设计稿，后续可以把 `metric-card` 最小高度和内部间距作为首个微调点。
- 项目概览高度略低于设计稿，但这和真实页脚、定价来源、项目行数有关，不建议为了贴图牺牲数据来源说明。
- 如果用户要求更像设计稿，应先给出具体区块标注，再改 CSS，避免全局拉大间距导致 `1080 x 720` 重新溢出。

## 5. 后续页面复用规则

每个页面从设计图进入实际开发时，都必须至少补齐下面 4 项：

- 区块拆分：列出页面的固定区块、数据区块和滚动区块。
- 比例测量：记录设计稿的主要区块宽高比例。
- 实现截图：至少生成 `1360 x 900` 与 `1080 x 720` 两张真实 Electron 截图。
- 差异决策：把差异分为必须修、可接受和因真实数据导致三类。

只有完成这 4 项，才能进入“页面可确认”状态。
