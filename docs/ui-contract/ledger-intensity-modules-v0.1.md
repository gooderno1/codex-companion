# Codex 账本页强度模块设计合同（v0.1）

- 创建时间：2026-06-04
- 页面范围：`Codex 账本` 第一行 `Token 走势拆解`、`周期洞察`，以及第二行右侧 `模型贡献`
- 对应版本基线：`v0.2.2-dev.69`
- 当前状态：细化确认稿，优先于示意图阅读

## 1. 模块边界

这份合同只约束下面三个模块：

- `Token 走势拆解`
- `周期洞察`
- `模型贡献`

不受它影响的模块：

- `周额度账本`
- `会话归因`

## 2. 周期状态

这三个模块不再共用同一套周期语义。

### 2.1 Token 走势拆解

`Token 走势拆解` 使用 `日 / 周 / 月`。

它回答的是“最近走势怎么变化”，所以必须保留较高时间分辨率：

- `日`：当前自然日 `00:00` 到快照时刻
- `周`：最近 `7` 个自然日
- `月`：最近 `30` 个自然日

横轴规则：

- `日`：固定 `小时`
- `周`：固定 `日期`
- `月`：`日期 / 周段`

交互规则：

- 若当前时间范围只有一种横轴，隐藏横轴切换控件。
- `月` 的 `周段` 模式把最近 `30` 天压缩成 `5` 个连续周段。
- 默认状态为 `周`。

### 2.2 周期洞察

`周期洞察` 不再跟随 `日 / 周 / 月`，改用 `近7天 / 近30天 / 累计`。

原因：

- `日` 视角会让右侧摘要过碎，和图表 hover 的信息层级重复。
- `周 / 月` 如果直接显示为两个字，容易被误解成自然周 / 自然月，而这里实际是滚动窗口。
- `全部` 边界不清，不知道是全部分页、全部会话，还是全部观测期。

定义：

- `近7天`：最近 `7` 个自然日
- `近30天`：最近 `30` 个自然日
- `累计`：从本地首个可观测 `CodexTokenEvent` 到当前快照时刻

命名规则：

- 文档与合同统一写 `累计`。
- 如果后续视觉稿里想强调“这是一个时间范围”，可以把按钮文案替换成 `全周期`，但数据口径不变。
- 不使用 `全部`。

默认状态：

- 默认 `近7天`

### 2.3 模型贡献

`模型贡献` 也不再跟随 `日 / 周 / 月`，改用 `近7天 / 近30天 / 累计`。

原因：

- 模型分布比趋势图更适合看一段时间内的聚合结果。
- `日` 粒度过短，模型构成极易抖动，不利于稳定阅读。

定义与命名规则完全跟 `周期洞察` 一致。

默认状态：

- 默认 `近7天`

## 3. Token 关系

当前设计必须遵守下面的关系：

- `总 Token = 输入总量 + 输出`
- `输入总量 = 原始输入 + 缓存输入`
- `缓存输入占比 = 缓存输入 / 输入总量`
- `推理 Token <= 输出`

重要约束：

- `input` 在当前采集口径下应视为 `输入总量`。
- `cachedInput` 是 `input` 的子集，不可与 `input` 再次并列相加。
- `reasoningOutput` 是 `output` 的子集，不可作为与 `output` 并列的独立总量段。

前端推导字段：

- `原始输入 = max(0, input - cachedInput)`

## 4. 纵轴定义

允许的纵轴只有 6 个：

- `总 Token`
- `输入总量`
- `缓存输入`
- `缓存输入占比`
- `输出`
- `推理 Token`

命名要求：

- 不要只写 `输入`，必须写 `输入总量`。
- `缓存输入占比` 必须明确分母是 `输入总量`。

## 5. 图表形态

### 5.1 总 Token

- 主柱使用三段堆叠：
  - `原始输入`
  - `缓存输入`
  - `输出`
- `推理 Token` 只作为 `输出` 内部子集标记：
  - 可用深色内嵌层
  - 或 hatch / 细描边
- 不允许把 `推理 Token` 当成第四段独立堆叠。

### 5.2 输入总量

- 使用两段堆叠：
  - `原始输入`
  - `缓存输入`

### 5.3 缓存输入 / 输出 / 推理 Token

- 使用单序列柱图。
- 不再显示构成堆叠。

### 5.4 缓存输入占比

- 使用百分比柱图。
- 纵轴固定 `0% - 100%`。
- tooltip 中同时给出绝对量，避免只剩百分比。

## 6. 纵轴与刻度

- 默认只显示左侧纵轴。
- 右侧纵轴默认不显示。
- 若保留右轴，只能做左轴镜像，不允许表达第二单位。

刻度规则：

- 绝对量按当前窗口最大值自动取友好刻度，例如：
  - `5000万`
  - `1亿`
  - `1.5亿`
- 百分比固定 `0 / 25 / 50 / 75 / 100`

## 7. Hover 与 Tooltip

悬停任一柱时，tooltip 必须统一展开：

- 完整时间范围
- 当前主指标值
- `总 Token`
- `输入总量`
- `原始输入`
- `缓存输入`
- `缓存输入占比`
- `输出`
- `推理 Token`
- `会话数`
- `API 等价成本`

补充规则：

- 若横轴为 `周段`，tooltip 需展开该周段覆盖的起止日期。
- `缓存输入占比` 纵轴下，tooltip 仍显示绝对 token 值。

## 8. 周期洞察

`周期洞察` 只跟随自己的 `近7天 / 近30天 / 累计` 状态变化，不跟随 `Token 走势拆解` 的 `日 / 周 / 月`，也不跟随纵轴变化。

固定 6 张卡：

- `窗口累计`
- `窗口均值`
- `峰值位置`
- `峰值用量`
- `单次峰值`
- `缓存输入占比`

### 8.1 计算规则

- `窗口累计`
  - 当前周期内 `Σtotal`
- `窗口均值`
  - `近7天`：最近 `7` 日平均每日 `total`
  - `近30天`：最近 `30` 日平均每日 `total`
  - `累计`：观测期平均每日 `total`
- `峰值位置`
  - `近7天`：Token 最高的日期
  - `近30天`：Token 最高的日期
  - `累计`：观测期内 Token 最高的日期
- `峰值用量`
  - 与 `峰值位置` 对应日期的 `total`
- `单次峰值`
  - 当前周期内单个会话 `total` 最大值
- `缓存输入占比`
  - 当前周期内 `ΣcachedInput / Σinput`

### 8.2 文案规则

- `窗口均值` 的副标题动态变化：
  - `近7天`：`7 日日均 Token`
  - `近30天`：`30 日日均 Token`
  - `累计`：`观测期日均 Token`
- `峰值位置` 的副标题不要再写成固定的 `峰值时段`。
- `累计` 视角下不要出现“全部”字样。

## 9. 模型贡献

`模型贡献` 跟随自己的 `近7天 / 近30天 / 累计` 状态，但不跟随 `Token 走势拆解` 的横轴与纵轴。

当前默认：

- 周期：`近7天`
- 默认排序：`Token` 绝对值倒序

交互规则：

- 不使用单独排序按钮。
- 采用点击列表头排序：
  - 初始状态：`Token` 倒序
  - 第一次点击任一字段：按该字段正序
  - 第二次点击同一字段：按该字段倒序
  - 切换到另一字段时重新从正序开始
- 当前页通用排序交互都优先使用“点表头切换排序”，而不是额外一排按钮。

允许排序列：

- `Token`
- `API 等价成本`
- `事件数`
- `占比`

说明：

- 你这轮提到的“默认最新提交，点表头正序 / 倒序”属于同一交互模式，但默认 `最新提交` 只适用于仓库表，不适用于第二页模型贡献。

## 10. 本轮定稿建议

建议直接定成下面这套用户可见命名：

- `Token 构成与强度` -> `Token 走势拆解`
- `强度摘要` -> `周期洞察`
- `模型构成` -> `模型贡献`

周期建议直接定成下面这两套：

- 趋势图：`日 / 周 / 月`
- 右侧两个模块：`近7天 / 近30天 / 累计`
