# Codex Companion 总览页 UI Contract（v0.1）

- 创建时间：2026-06-03
- 适用版本：`v0.2.2-dev.78` 之后的总览页实现
- 页面来源：`docs/page-design-spec-v0.3.md` 第 2 节
- 状态：进入实际开发前的最终确认稿

## 1. 页面目标

总览页用于快速回答三件事：

- 今天 Codex 用得是否正常
- 当前 `5H` 与 `周额度窗口` 是否紧张
- 当前周期内，哪些项目消耗了更多 Token，并对应了多少代码活动

## 2. 页面结构

总览页由 5 个区域构成：

1. 左侧导航
2. 顶部工具栏
3. 顶部四个指标卡
4. 中部两张额度卡
5. 底部项目概览表

## 2.1 视口约束

实现时至少满足下面两种窗口状态：

- 标准桌面窗口：`1360 x 900`
- 最小桌面窗口：`1080 x 720`
- 全屏窗口

约束：

- 不依赖全屏才能完整查看页面
- 左侧导航与顶部工具栏不得把主要内容挤出可视区
- 超过最小桌面窗口时，应用壳层应按比例缩放，不用全局滚动解决显示不全
- 只有数据表等明确滚动容器允许内部滚动
- 提交前必须用真实 Electron 窗口截图验证 `自然时间` 与 `计费时间` 两种状态的 `1360 x 900` 与 `1080 x 720`，不能只靠构建通过或人工运行判断；截图前必须强制生成 `live` 快照并广播到渲染端，若只能读取缓存则截图失败，避免旧缓存误导图审

## 2.2 加载约束

启动时不能等待完整 Codex / Git 采集完成后才显示首屏。

规则：

- 首屏优先显示缓存快照或 `采集中` 状态
- 真实 Codex / Git 采集在后台刷新
- 后台刷新完成后替换为 `live` 快照
- 主动点击刷新时才显示明确的刷新状态
- 顶栏下方的刷新反馈条只在刷新进行中或刚完成时临时显示；完成或失败后展示约 `5s` 后消失

## 2.3 实时刷新约束

总览页数据必须能在应用运行期间持续刷新，不能只在启动和手动点击刷新时更新。

规则：

- 主进程负责刷新节奏，默认每 `5` 分钟后台采集一次 `DashboardSnapshot`
- 应用启动时优先展示缓存快照；实时采集延迟到后台执行，避免打开应用时被完整 Codex + Git 扫描阻塞
- 启动时如果先返回缓存或 `pending` 快照，后台采集完成后必须通过 `dashboard:updated` 广播给所有已打开页面
- 手动点击刷新同样必须在采集成功后广播最新快照，避免主窗口、挂件和托盘状态不一致
- 渲染端只订阅 `dashboard:updated` 更新页面，不自行发起高频轮询
- 自动刷新不能触发首屏加载遮罩或按钮 `刷新中` 状态；只有用户主动点击刷新时才显示明确刷新反馈
- 手动刷新期间按钮文案显示 `采集中` 并禁用重复点击；完成后临时反馈条显示 `刷新完成 / 已回退缓存` 与 `sourceHealth.refresh` 统计，约 `5s` 后自动消失
- 后台刷新广播完成后临时反馈条显示 `后台刷新完成`，不能静默失败或只更新快照时间
- 刷新反馈必须来自 `DashboardSnapshot.sourceHealth.refresh`，不能只用前端本地计时推断
- 设置页必须展示最近刷新历史，至少区分 `手动刷新 / 自动刷新 / 启动刷新 / 后台刷新`
- 刷新失败时保留上一张可用快照，并只展示轻量错误提示，不清空页面主体

## 2.4 视觉细节约束

总览页以已确认设计图 `docs/assets/design/v0.3.3/overview-natural-time.png` 为当前视觉基准。

### 颜色

基础颜色：

- 页面背景：浅蓝白，接近 `#f8fbff`，只允许极弱蓝白渐变，不做明显雾面灰底
- 左侧导航：白到浅蓝白渐变，接近 `#ffffff -> #f8fbff`
- 右侧工作区：接近白底，允许极弱 `#f8fbff` 过渡，不做独立厚重浮层
- 主卡片：接近纯白 `#ffffff`
- 弱卡片：接近 `#f7fbff`
- 主描边：浅蓝灰，接近 `rgba(15, 111, 255, 0.10)`
- 强描边：主蓝透明度提高，接近 `rgba(15, 111, 255, 0.16)`

文字颜色：

- 主标题、主数字：深墨色，接近 `#111827`
- 正文、表格正文和普通按钮：蓝灰色，接近 `#334155`
- 副标题、说明、表头、页脚：中性蓝灰，接近 `#64748b`
- 弱辅助文字：更浅的蓝灰色，接近 `#94a3b8`，只用于证据、定价来源和低权重说明
- 禁止把所有非主标题文字都压成深墨色，否则页面会比设计稿更重

强调色：

- 主蓝：接近 `#0f6fff`
- 青色：接近 `#12b8d7`
- 成功绿：接近 `#16a34a`
- 警告橙：接近 `#d97706`
- 风险红：接近 `#dc2626`

### 阴影与边框

- 壳层阴影必须轻，避免灰色玻璃感
- 卡片阴影只用于分层，不能让背景显脏
- 边框优先使用浅蓝灰，不使用纯灰重边框
- 右侧主工作区外层不做强浮层卡片，不使用厚重阴影和过大圆角
- 顶部四卡与额度卡优先接近白底，只允许非常弱的蓝白或暖白渐变
- 应用壳层外边距与左右间隔必须克制，避免缩小右侧真实内容面积

### 组件级配色约束

- 左侧品牌标题使用主标题色；品牌说明使用辅助色；`本机读取 · 无上传` 使用正文色和绿色状态点。
- 顶部页面标题使用主标题色；页面副标题和 `时间视角` 标签使用辅助色。
- 顶部四卡标题使用主标题色，主数字使用深墨色但不使用等宽字体，变化说明按正负使用绿 / 红；正常 `已观测` 不在单卡内重复展示，只有 `待刷新 / 未观测 / 数据过期` 等异常态才显示右上角状态标签。
- 额度卡标题使用主标题色；右侧明细标签使用正文色，数值使用深墨色；底部注记使用辅助色，证据使用弱辅助色。
- 项目表表头不强制全大写，使用辅助色；表格正文使用正文色，项目名加粗但不额外加深到纯黑。
- 页脚属于最低权重信息，正文使用辅助色，chip 使用浅色底和浅描边。

## 3. 左侧导航

固定项：

- 产品图标
- `Codex Companion`
- `非官方 Codex 本机仪表盘`
- `本机读取 · 无上传`
- `总览`
- `Codex 账本`
- `代码仓库`
- `设置`
- 版本号
- `非官方工具`

交互规则：

- `总览` 为当前激活项。
- `设置` 固定在最底部，始终可见。
- 左侧不显示快照时间。
- 顶部品牌区必须先显示产品图标和 `Codex Companion` 标题，标题顶线与图标顶线对齐。
- `非官方 Codex 本机仪表盘` 和 `本机读取 · 无上传` 作为标题下方说明，不得放在标题上方导致错位。
- 产品图标必须使用本项目非官方自定义几何标识，视觉尺寸接近设计稿，不使用 OpenAI / Codex 官方 logo。
- 产品图标与导航图标统一从 `src/renderer/icons.tsx` 维护，页面组件只引用 `BrandMark` 与 `Glyph`，避免后续页面各自复制图标实现导致错位或风格漂移。
- 品牌图标与标题之间保持设计稿接近的横向间距，不能因为间距过小让标题贴近图标，也不能让标题相对图标下坠。
- 品牌文字组需要做少量视觉基线补偿，确保标题顶线与图标顶线接近；不能出现标题明显高于图标或低于图标的错位。
- 品牌图标视觉盒建议控制在 `56px` 左右，标题组顶部不再额外下移；图标和标题共同形成一个首屏品牌块，说明文字只作为下方辅助信息。
- 导航项图标固定为：`总览=首页`、`Codex 账本=文档账本`、`代码仓库=代码方块`、`设置=齿轮`。
- 导航图标必须使用本项目自定义内联 SVG，不使用官方或第三方品牌图标。
- 导航图标自身不使用额外白色胶囊背景；当前页由整行浅蓝底和蓝色图标表达激活态。
- 导航项遵循设计稿的单行结构，只显示图标和主标签，不显示二级说明；左侧导航不承担页面摘要功能。

## 4. 顶部工具栏

左侧：

- 页面标题：`总览`
- 页面副标题：`Codex 使用、额度与本地工程活动`
- 标题与副标题横向展示为同一信息组

中部：

- 单行展示：`时间视角  自然时间  计费时间`
- 位置应处于顶部工具栏几何中段；不能被标题组弹性宽度推到左侧，也不能贴近右侧操作区。

右侧：

- 数据状态标签：`已观测 / 待刷新 / 未观测 / 数据过期`
- 刷新按钮
- 唯一快照时间：`快照 HH:mm`

交互规则：

- 不展示额外眉标，例如 `桌面总控台`
- `自然时间 / 计费时间` 为页级切换。
- 页级切换只改变统计口径，不改变页面结构。
- 时间切换使用无边框文本切换。
- `时间视角` 标签和两个切换项必须在同一行内，不拆成上下两行。
- 时间切换内部不允许换行；在较窄窗口优先压缩标题副标题间距或右侧操作间距，不先拆开时间切换。
- 顶部工具栏在桌面宽度下必须保持一行，不允许把时间视角整体挪到标题下方；如果空间不足，优先缩短右侧快照和按钮间距。
- `时间视角` 标签、`自然时间` 和 `计费时间` 必须放在同一个 `topbar-mode-switch` inline-flex 容器内，三个文本不能由换行、段落或独立区块拆开。
- 顶部工具栏布局应采用“三列”结构：左侧标题组、中部视角控件、右侧操作区；中部视角控件需要在可用顶栏宽度内居中对齐。
- 桌面宽度下不使用纯 `flex-start` 或 `space-between` 驱动中部控件位置；否则容易让时间视角偏左或被挤到右侧操作区旁边。
- 顶部数据状态标签只显示文字，不显示额外图标；设计稿中它是轻量状态胶囊，不是操作按钮。
- 顶部工具栏高度应接近设计稿，不得因额外层级被撑高。

## 5. 顶部四卡

### 5.1 固定字段

四卡字段在 `自然时间 / 计费时间` 下保持一致：

- `今日 Token`
- `本周 Token`
- `本月 Token`
- `今日代码改动`

### 5.2 展示规则

每张卡片包含：

- 指标图标
- 标题
- 主数字
- 次级说明
- 状态标签

约束：

- 指标图标在左侧，标题、主数字和次级说明在右侧形成内容组；图标与内容组整体在卡片内部居中
- 标题、主数字和次级说明需要在内容组内居中对齐，不能左贴卡片边缘
- 指标图标尺寸按卡片尺寸自适应，避免标准窗口下过小、最小窗口下过大
- 状态标签展示单卡异常观测状态，固定在卡片右上角，不能单独占用一整行；正常 `已观测` 由顶部工具栏全局状态表达，不在四张指标卡内重复显示
- 不在每张卡右上角重复展示 `自然日 / 自然周 / 自然月 / 计费周` 等周期标签
- 状态标签必须跟随单张卡片的数据可观测性；不能所有卡片无条件沿用全局 `sourceHealth.sourceStatus`。
- 当计费时间下 `本月 Token` 的计费月时间口径可由设置推导时，主值显示当前计费月 Token；默认起始日为每月 `1` 日，因此当前默认与自然月一致。
- 当未来配置的计费月起始日缺失或无效时，必须降级回每月 `1` 日，不能把字段改成其他指标。
- 当单卡状态为 `已观测` 时，不渲染状态标签；当单卡状态为 `待刷新 / 未观测 / 数据过期` 时，必须渲染状态标签，避免异常状态被全局状态掩盖。
- 主数字只显示一次
- 不重复展示完整 Token 数值
- 不展示会话数、事件数、等价成本
- 不展示趋势曲线
- 指标卡高度应接近设计稿的舒展比例，不能为了压缩页面把主数字、说明和右上角状态标签挤在一起
- 指标图标视觉高度应接近右侧三行文字的总高度，建议 `64px - 72px`；图标与文字组间距应收紧到约 `14px - 18px`，让图标和文字形成一个指标组，而不是两个独立视觉中心。
- 顶部四卡应优先通过卡片自身最小高度、内部居中、图标尺寸和右上角状态位置来接近设计稿，不通过全局增大页面区块间距实现。
- 状态标签应小尺寸贴右上角，和标题 / 主数字保持安全间隔；在 `1080 x 720` 下仍必须完整显示项目概览和页脚。
- 图标、标题和主数字的微调必须只影响内部视觉权重，不改变字段、单位、状态文案和统计口径。

### 5.3 次级说明

默认使用变化说明：

- `较昨日 +12.4%`
- `较上周 +8.7%`
- `较上月 +15.2%`
- `较昨日 -3.1%`

如果上一周期为 `0` 且当前周期大于 `0`，百分比分母不可定义，但数据并未缺失，应显示新增语义：

- `较昨日 新增`
- `较上周 新增`
- `较上月 新增`

`今日代码改动` 的 `较昨日` 使用昨日自然日 Git `changedLines = additions + deletions` 作为分母；昨日 Git 区间有数据时必须展示百分比，例如 `较昨日 +41.5%`，不能因为昨日 token 窗口为空而降级为 `新增`。

如果某项当前无法提供稳定变化值，可降级为：

- `数据待补齐`
- `未观测`

### 5.4 单位规则

Token 数字自动单位：

- `< 10,000`：整数
- `>= 10,000 && < 100,000,000`：`万`
- `>= 100,000,000`：`亿`

代码改动：

- 使用 `行`

### 5.5 口径规则

`自然时间`：

- `今日 Token`：自然日
- `本周 Token`：自然周
- `本月 Token`：自然月
- `今日代码改动`：自然日

`计费时间`：

- `今日 Token`：当前日
- `本周 Token`：当前周额度窗口
- `本月 Token`：当前计费月 Token 窗口；默认从每月 `1` 日 `00:00` 开始，因此当前默认与自然月一致。后续设置页允许用户选择每月第几天作为计费月起始日。
- `今日代码改动`：当前日

## 6. 中部两张额度卡

### 6.1 固定字段

中部固定两张卡：

- `5H 额度窗口`
- `周额度窗口`

标题规则：

- 卡片标题只写一次，不再额外显示一行 `额度窗口`
- 标题可配小图标，但不得因为辅助标签占用额外行高

### 6.2 每张卡结构

左半区：

- 环形进度
- 中心主数字：剩余百分比
- 下方文案：重置时间与当前额度周期起止合并为一行，例如 `重置 08:25 · 周期 03:25 - 08:25`
- 周期范围需按跨度自适应：同日短周期显示 `HH:mm - HH:mm`；跨日但小于 24 小时显示 `MM/DD HH:mm - MM/DD HH:mm`；周额度等多日周期显示 `MM/DD - MM/DD`，避免出现 `周期 09:02 - 09:02` 这类看似零长度的文案

右半区：

- `Token 用量`
- `API 等价成本`
- `代码行数`
- `会话数`

展示规则：

- 右半区每一行都带小图标，分别对应 Token、成本、代码和会话
- `Token 用量` 的值使用自动单位并追加 `tok` 后缀，例如 `21.5 万 tok`、`1.2 亿 tok`，只用于额度卡右侧明细；顶部四卡和项目概览继续使用无后缀紧凑单位

右上角：

- 数据状态标签：`已观测 / 待刷新 / 未观测 / 数据过期`

底部：

- Top 3 模型占比条
- 额度观测证据：`观测 N 次 · 重置 N 次`
- 额度观测证据应并入 `Top 3 模型占比` 标题行右侧，不再作为独立底部说明行，避免在设计稿之外多占一行高度

### 6.3 边界规则

当前卡片中心数字统一显示：

- `剩余百分比`

数据口径：

- 圆环中心 `剩余百分比` 优先来自当前额度周期的累计口径：`PeriodMetric.quotaEvidence.remainingPercent`。
- 如果当前周期暂时缺少 `quotaEvidence`，圆环才降级使用最近一次 Codex 原始 `rate_limits.<primary|secondary>.used_percent`，计算为 `100 - used_percent`。
- 圆环弧线也必须使用同一个 `剩余百分比`，不能使用已用百分比；否则会出现中心显示 `94% 剩余` 但弧线只有已用部分的反向表达。
- 右侧 `Token 用量 / API 等价成本 / 会话数 / Top 3 模型占比` 来自当前额度周期内的真实 token 增量。
- 当前额度周期边界由最近一次 `rate_limits.<primary|secondary>.resets_at` 与 `window_minutes` 反推。
- 如果本机同时存在多个 `rate_limits` 池，可见 `5H / 周额度` 优先使用主额度池 `limit_id=codex`；模型或实验额度池不能因为记录时间更新而覆盖主额度显示。
- 当前周期的额度观测证据必须只聚合同一 `limit_id / limit_name` 的样本，不能混合不同额度池。
- token 增量优先使用同一 session 内 `total_token_usage` 累计快照差值，不直接把所有 `total_token_usage` 相加。
- 无 token 增量但携带 `rate_limits` 的记录仍作为额度观测点保留，用于判断周期与重置。
- `代码行数` 来自同一额度周期边界内的本地 Git 活动。
- `观测 N 次` 来自当前额度周期内有效 `rate_limits` 观测点数量；采集范围至少覆盖近 `60` 天，使前几周计费周期可用于比较。
- `重置 N 次` 来自同一 session 相邻额度观测中符合高水位下降与 `resets_at` 后移条件的重置识别。
- 套餐价值折算字段只作为数据层和挂件摘要使用时，必须用当前周期累计已用百分比，不使用最近一次原始百分比。
- `可观测月额度` 与顶部 `本月 Token` 不是同一概念；即使计费月 Token 默认可按每月 1 日计算，月额度仍必须等待 Codex 原始 `rate_limits` 暴露月级窗口后才可展示。

不显示：

- 剩余 Token
- 预计可用时长

- 口径说明 `圆环=周期累计余量；右侧=当前周期累计。` 保留在数据层和文档中，不在总览页额度卡内作为独立行展示；额度类型已经由卡片标题表达，页面不再重复 `5H`、`周额度` 或 `额度窗口` 字样。
- 证据文案只写 `观测 N 次 · 重置 N 次`，不再额外重复 `额度观测`，且必须与 `Top 3 模型占比` 保持同一行。
- 由于顶部四卡使用自然日 / 自然周 / 自然月，额度卡使用真实额度周期，额度卡必须展示周期起止，避免用户把自然日累计和当前 5H 周期累计误认为同一口径；周期起止必须与重置文案合并展示，不新增独立行高。
- 圆环内文字顺序为上方小字 `剩余量`、中间大数字百分比；百分比必须处于圆环中心视觉位置。

## 7. 项目概览

### 7.1 结构

区域标题：

- `项目概览`
- 不使用 `当前周期内的项目消耗与工程活动` 作为主标题
- 标题左侧信息组必须展示为：`项目概览  日 / 周 / 月` 或 `项目概览  5H / 周额度`
- 二级周期切换紧跟标题右侧，不放到卡片右上角

能力：

- 可滚动
- 默认按 `最近活动` 倒序，即最新项目活动优先
- 自然时间下默认选中 `周`，计费时间下默认选中 `周额度`，使项目概览首屏优先展示更稳定的周期数据，并与设计基准图默认高亮一致
- 支持点击表头排序，不再使用右上角排序按钮
- 展示所有已发现本地项目；当前周期无活动的项目保留在表格中，数值为 0，最近活动为 `--`

### 7.2 表头排序

- 可排序表头：`项目`、`Token`、`API 等价成本`、`代码行数`、`提交`、`会话`、`最近活动`
- 默认排序：`最近活动` 倒序
- 点击非当前排序表头：按该字段正序排序
- 再次点击当前排序表头：在正序 / 倒序之间切换
- 活动排序列在表头使用轻量蓝色状态和方向箭头提示，不新增独立排序按钮行

### 7.3 二级周期切换

当页级视角为 `自然时间`：

- `日`
- `周`
- `月`

当页级视角为 `计费时间`：

- `5H`
- `周额度`

布局规则：

- 二级周期切换属于项目概览标题组，放在标题右侧。
- 排序交互属于表格表头，不占用卡片右上角工具区。
- 不把二级周期切换和排序切换堆叠在同一个右侧工具区，也不再渲染 `按 Token / 按成本 / 按代码行 / 按最近活动` chip 按钮。
- 用户切换周期后保持当前选择；上述默认值只用于首次进入总览页。

### 7.4 表格字段

- `项目`
- `Token`
- `API 等价成本`
- `代码行数`
- `提交`
- `会话`
- `最近活动`

展示规则：

- `项目` 列必须包含项目小图标和项目名，图标使用本项目自定义轻量图标，不使用第三方或官方 logo。
- 项目图标颜色可按项目名稳定映射，目的是提供可扫读锚点，不表示真实仓库类型或官方身份。
- 表格需要保留浅色横向行线和纵向列线，形成接近设计稿的账本表格结构；列线只辅助扫读，不能强到抢过文字和项目图标。

## 7.5 页脚数据来源

总览页中，页脚数据来源归属于项目概览卡底部，视觉上必须和项目表格属于同一张底部卡片；不在项目卡外另起一个独立页脚条。

页脚必须展示：

- 数据来源说明：`Codex 本地 sessions、archived_sessions、本地 Git；不读取云端仓库信息`
- `session` 文件数
- `archived` 文件数
- 仓库数
- 定价来源说明

## 8. 状态与降级规则

如果当前数据源不足，页面按以下优先级降级：

1. 保留字段结构
2. 主数字改为 `未观测` 或 `--`
3. 次级说明改为 `数据待补齐`
4. 状态标签改为 `未观测 / 待刷新 / 数据过期`

禁止：

- 因为缺字段而直接替换四卡字段
- 因为缺月窗口数据而把 `本月 Token` 换成完全不同的指标

## 9. 不实现项

当前总览页不实现：

- 四卡内趋势曲线
- 四卡内会话数 / 事件数 / 成本辅助信息
- 中部卡片的剩余 Token
- 中部卡片的预计可用时长
- 项目表中的主模型列
