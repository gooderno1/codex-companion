# Codex Companion 总览页 UI Contract（v0.1）

- 创建时间：2026-06-03
- 适用版本：`v0.2.2-dev.34` 之后的总览页实现
- 页面来源：`docs/page-design-spec-v0.3.md` 第 2 节
- 状态：进入实际开发前的最终确认稿

## 1. 页面目标

总览页用于快速回答三件事：

- 今天 Codex 用得是否正常
- 当前 `5H` 与 `周额度窗口` 是否紧张
- 当前周期内，哪些项目消耗了更多 Token，并对应了多少代码活动

## 2. 页面结构

总览页由 5 个区域构成：

1. 左侧导航
2. 顶部工具栏
3. 顶部四个指标卡
4. 中部两张额度卡
5. 底部项目概览表

## 2.1 视口约束

实现时至少满足下面两种窗口状态：

- 标准桌面窗口：`1360 x 900`
- 最小桌面窗口：`1080 x 720`
- 全屏窗口

约束：

- 不依赖全屏才能完整查看页面
- 左侧导航与顶部工具栏不得把主要内容挤出可视区
- 超过最小桌面窗口时，应用壳层应按比例缩放，不用全局滚动解决显示不全
- 只有数据表等明确滚动容器允许内部滚动
- 提交前必须用真实 Electron 窗口截图验证 `1360 x 900` 与 `1080 x 720`，不能只靠构建通过或人工运行判断

## 2.2 加载约束

启动时不能等待完整 Codex / Git 采集完成后才显示首屏。

规则：

- 首屏优先显示缓存快照或 `采集中` 状态
- 真实 Codex / Git 采集在后台刷新
- 后台刷新完成后替换为 `live` 快照
- 主动点击刷新时才显示明确的刷新状态

## 2.3 视觉细节约束

总览页以已确认设计图 `docs/assets/design/v0.3.3/overview-natural-time.png` 为当前视觉基准。

### 颜色

基础颜色：

- 页面背景：浅蓝白，接近 `#f8fbff`，只允许极弱蓝白渐变，不做明显雾面灰底
- 左侧导航：白到浅蓝白渐变，接近 `#ffffff -> #f8fbff`
- 右侧工作区：接近白底，允许极弱 `#f8fbff` 过渡，不做独立厚重浮层
- 主卡片：接近纯白 `#ffffff`
- 弱卡片：接近 `#f7fbff`
- 主描边：浅蓝灰，接近 `rgba(15, 111, 255, 0.12)`
- 强描边：主蓝透明度提高，接近 `rgba(15, 111, 255, 0.22)`

文字颜色：

- 主标题、主数字：深墨色，接近 `#111827`
- 正文、表格正文和普通按钮：蓝灰色，接近 `#475569`
- 副标题、说明、表头、页脚：中性蓝灰，接近 `#64748b`
- 弱辅助文字：更浅的蓝灰色，接近 `#7c8ca3`，只用于证据、定价来源和低权重说明
- 禁止把所有非主标题文字都压成深墨色，否则页面会比设计稿更重

强调色：

- 主蓝：接近 `#0f6fff`
- 青色：接近 `#12b8d7`
- 成功绿：接近 `#16a34a`
- 警告橙：接近 `#d97706`
- 风险红：接近 `#dc2626`

### 阴影与边框

- 壳层阴影必须轻，避免灰色玻璃感
- 卡片阴影只用于分层，不能让背景显脏
- 边框优先使用浅蓝灰，不使用纯灰重边框
- 右侧主工作区外层不做强浮层卡片，不使用厚重阴影和过大圆角
- 顶部四卡与额度卡优先接近白底，只允许非常弱的蓝白或暖白渐变
- 应用壳层外边距与左右间隔必须克制，避免缩小右侧真实内容面积

### 组件级配色约束

- 左侧品牌标题使用主标题色；品牌说明使用辅助色；`本机读取 · 无上传` 使用正文色和绿色状态点。
- 顶部页面标题使用主标题色；页面副标题和 `时间视角` 标签使用辅助色。
- 顶部四卡标题使用主标题色，主数字使用深墨色但不使用等宽字体，变化说明按正负使用绿 / 红，状态标签使用浅绿底。
- 额度卡标题使用主标题色；右侧明细标签使用正文色，数值使用深墨色；底部注记使用辅助色，证据使用弱辅助色。
- 项目表表头不强制全大写，使用辅助色；表格正文使用正文色，项目名加粗但不额外加深到纯黑。
- 页脚属于最低权重信息，正文使用辅助色，chip 使用浅色底和浅描边。

## 3. 左侧导航

固定项：

- 产品图标
- `Codex Companion`
- `非官方 Codex 本机仪表盘`
- `本机读取 · 无上传`
- `总览`
- `Codex 账本`
- `代码仓库`
- `设置`
- 版本号
- `非官方工具`

交互规则：

- `总览` 为当前激活项。
- `设置` 固定在最底部，始终可见。
- 左侧不显示快照时间。
- 顶部品牌区必须先显示产品图标和 `Codex Companion` 标题，标题顶线与图标顶线对齐。
- `非官方 Codex 本机仪表盘` 和 `本机读取 · 无上传` 作为标题下方说明，不得放在标题上方导致错位。
- 产品图标必须使用本项目非官方自定义几何标识，视觉尺寸接近设计稿，不使用 OpenAI / Codex 官方 logo。
- 品牌图标与标题之间保持设计稿接近的横向间距，不能因为间距过小让标题贴近图标，也不能让标题相对图标下坠。
- 品牌文字组需要做少量视觉基线补偿，确保标题顶线与图标顶线接近；不能出现标题明显高于图标或低于图标的错位。
- 导航项图标固定为：`总览=首页`、`Codex 账本=文档账本`、`代码仓库=代码方块`、`设置=齿轮`。
- 导航图标必须使用本项目自定义内联 SVG，不使用官方或第三方品牌图标。
- 导航图标自身不使用额外白色胶囊背景；当前页由整行浅蓝底和蓝色图标表达激活态。
- 导航项遵循设计稿的单行结构，只显示图标和主标签，不显示二级说明；左侧导航不承担页面摘要功能。

## 4. 顶部工具栏

左侧：

- 页面标题：`总览`
- 页面副标题：`Codex 使用、额度与本地工程活动`
- 标题与副标题横向展示为同一信息组

中部：

- 单行展示：`时间视角  自然时间  计费时间`

右侧：

- 数据状态标签：`已观测 / 待刷新 / 未观测 / 数据过期`
- 刷新按钮
- 唯一快照时间：`快照 HH:mm`

交互规则：

- 不展示额外眉标，例如 `桌面总控台`
- `自然时间 / 计费时间` 为页级切换。
- 页级切换只改变统计口径，不改变页面结构。
- 时间切换使用无边框文本切换。
- `时间视角` 标签和两个切换项必须在同一行内，不拆成上下两行。
- 时间切换内部不允许换行；在较窄窗口优先压缩标题副标题间距或右侧操作间距，不先拆开时间切换。
- 顶部工具栏在桌面宽度下必须保持一行，不允许把时间视角整体挪到标题下方；如果空间不足，优先缩短右侧快照和按钮间距。
- 顶部工具栏高度应接近设计稿，不得因额外层级被撑高。

## 5. 顶部四卡

### 5.1 固定字段

四卡字段在 `自然时间 / 计费时间` 下保持一致：

- `今日 Token`
- `本周 Token`
- `本月 Token`
- `今日代码改动`

### 5.2 展示规则

每张卡片包含：

- 指标图标
- 标题
- 主数字
- 次级说明
- 状态标签

约束：

- 指标图标在左侧，标题、主数字和次级说明在右侧形成内容组
- 状态标签展示数据源观测状态，位于卡片底部视觉区域
- 不在每张卡右上角重复展示 `自然日 / 自然周 / 自然月 / 计费周` 等周期标签
- 主数字只显示一次
- 不重复展示完整 Token 数值
- 不展示会话数、事件数、等价成本
- 不展示趋势曲线
- 指标卡高度应接近设计稿的舒展比例，不能为了压缩页面把状态标签挤到主数字附近
- 顶部四卡应优先通过卡片自身最小高度、内部行距和底部状态区位置来接近设计稿，不通过全局增大页面区块间距实现。
- 状态标签应处于卡片底部视觉区域，和主数字 / 变化说明保持明确间隔；在 `1080 x 720` 下仍必须完整显示项目概览和页脚。
- 图标、标题和主数字的微调必须只影响内部视觉权重，不改变字段、单位、状态文案和统计口径。

### 5.3 次级说明

默认使用变化说明：

- `较昨日 +12.4%`
- `较上周 +8.7%`
- `较上月 +15.2%`
- `较昨日 -3.1%`

如果某项当前无法提供稳定变化值，可降级为：

- `数据待补齐`
- `未观测`

### 5.4 单位规则

Token 数字自动单位：

- `< 10,000`：整数
- `>= 10,000 && < 100,000,000`：`万`
- `>= 100,000,000`：`亿`

代码改动：

- 使用 `行`

### 5.5 口径规则

`自然时间`：

- `今日 Token`：自然日
- `本周 Token`：自然周
- `本月 Token`：自然月
- `今日代码改动`：自然日

`计费时间`：

- `今日 Token`：当前日
- `本周 Token`：当前周额度窗口
- `本月 Token`：当前计费月窗口；若当前版本还没有稳定月窗口数据，则保持字段不变，但状态显示 `未观测` 或 `待补齐`
- `今日代码改动`：当前日

## 6. 中部两张额度卡

### 6.1 固定字段

中部固定两张卡：

- `5H 额度窗口`
- `周额度窗口`

标题规则：

- 卡片标题只写一次，不再额外显示一行 `额度窗口`
- 标题可配小图标，但不得因为辅助标签占用额外行高

### 6.2 每张卡结构

左半区：

- 环形进度
- 中心主数字：剩余百分比
- 下方文案：重置时间与当前额度周期起止合并为一行，例如 `重置 08:25 · 周期 03:25 - 08:25`

右半区：

- `Token 用量`
- `API 等价成本`
- `代码行数`
- `会话数`

展示规则：

- 右半区每一行都带小图标，分别对应 Token、成本、代码和会话

右上角：

- 数据状态标签：`已观测 / 待刷新 / 未观测 / 数据过期`

底部：

- Top 3 模型占比条
- 边界注记
- 额度观测证据：`观测 N 次 · 重置 N 次`

### 6.3 边界规则

当前卡片中心数字统一显示：

- `剩余百分比`

数据口径：

- 圆环中心 `剩余百分比` 来自最近一次 Codex 原始 `rate_limits.<primary|secondary>.used_percent`，计算为 `100 - used_percent`。
- 圆环弧线也必须使用同一个 `剩余百分比`，不能使用已用百分比；否则会出现中心显示 `99% 剩余` 但弧线只有极小一段的反向表达。
- 右侧 `Token 用量 / API 等价成本 / 会话数 / Top 3 模型占比` 来自当前额度周期内的真实 token 增量。
- 当前额度周期边界由最近一次 `rate_limits.<primary|secondary>.resets_at` 与 `window_minutes` 反推。
- token 增量优先使用同一 session 内 `total_token_usage` 累计快照差值，不直接把所有 `total_token_usage` 相加。
- 无 token 增量但携带 `rate_limits` 的记录仍作为额度观测点保留，用于判断周期与重置。
- `代码行数` 来自同一额度周期边界内的本地 Git 活动。
- `观测 N 次` 来自当前额度周期内有效 `rate_limits` 观测点数量。
- `重置 N 次` 来自同一 session 相邻额度观测中符合高水位下降与 `resets_at` 后移条件的重置识别。
- 套餐价值折算字段只作为数据层和挂件摘要使用时，必须用当前周期累计已用百分比，不使用圆环的最近一次百分比。

不显示：

- 剩余 Token
- 预计可用时长

固定注记：

- `圆环=最近余量；右侧=当前周期累计。`
- 注记必须保持短句，不在总览页底部展开 `rate_limits` 字段名、历史重置段和计算公式。
- 注记和观测证据应尽量保持同一视觉行；证据文案只写 `观测 N 次 · 重置 N 次`，不再额外重复 `额度观测`。
- 由于顶部四卡使用自然日 / 自然周 / 自然月，额度卡使用真实额度周期，额度卡必须展示周期起止时间，避免用户把自然日累计和当前 5H 周期累计误认为同一口径；周期起止必须与重置文案合并展示，不新增独立行高。

## 7. 项目概览

### 7.1 结构

区域标题：

- `项目概览`
- 不使用 `当前周期内的项目消耗与工程活动` 作为主标题
- 标题左侧信息组必须展示为：`项目概览  日 / 周 / 月` 或 `项目概览  5H / 周额度`
- 二级周期切换紧跟标题右侧，不放到卡片右上角

能力：

- 可滚动
- 默认按 Token 降序
- 支持排序切换
- 展示所有已发现本地项目；当前周期无活动的项目保留在表格中，数值为 0，最近活动为 `--`

### 7.2 排序项

- `按 Token`
- `按成本`
- `按代码行`
- `按最近活动`

### 7.3 二级周期切换

当页级视角为 `自然时间`：

- `日`
- `周`
- `月`

当页级视角为 `计费时间`：

- `5H`
- `周额度`

布局规则：

- 二级周期切换属于项目概览标题组，放在标题右侧。
- 排序切换属于表格操作，单独靠右展示。
- 不把二级周期切换和排序切换堆叠在同一个右侧工具区。

### 7.4 表格字段

- `项目`
- `Token`
- `API 等价成本`
- `代码行数`
- `提交`
- `会话`
- `最近活动`

展示规则：

- `项目` 列必须包含项目小图标和项目名，图标使用本项目自定义轻量图标，不使用第三方或官方 logo。
- 项目图标颜色可按项目名稳定映射，目的是提供可扫读锚点，不表示真实仓库类型或官方身份。
- 表格需要保留浅色横向行线和纵向列线，形成接近设计稿的账本表格结构；列线只辅助扫读，不能强到抢过文字和项目图标。

## 7.5 页脚数据来源

总览页中，页脚数据来源归属于项目概览卡底部，视觉上必须和项目表格属于同一张底部卡片；不在项目卡外另起一个独立页脚条。

页脚必须展示：

- 数据来源说明：`Codex 本地 sessions、archived_sessions、本地 Git；不读取云端仓库信息`
- `session` 文件数
- `archived` 文件数
- 仓库数
- 定价来源说明

## 8. 状态与降级规则

如果当前数据源不足，页面按以下优先级降级：

1. 保留字段结构
2. 主数字改为 `未观测` 或 `--`
3. 次级说明改为 `数据待补齐`
4. 状态标签改为 `未观测 / 待刷新 / 数据过期`

禁止：

- 因为缺字段而直接替换四卡字段
- 因为缺月窗口数据而把 `本月 Token` 换成完全不同的指标

## 9. 不实现项

当前总览页不实现：

- 四卡内趋势曲线
- 四卡内会话数 / 事件数 / 成本辅助信息
- 中部卡片的剩余 Token
- 中部卡片的预计可用时长
- 项目表中的主模型列

## 10. 开发前检查

进入实际开发前，这 5 项必须成立：

1. 总览页设计图已确认
2. 本 `ui-contract` 已确认
3. token 文件已建立
4. 组件映射表已建立
5. 截图基线方案已选定

提交实现前，这 4 项必须成立：

1. `npm run build` 通过
2. `1360 x 900` 真实 Electron 截图完整显示左侧导航、顶部工具栏、四卡、两张额度卡、项目概览和页脚
3. `1080 x 720` 真实 Electron 截图完整显示左侧导航、顶部工具栏、四卡、两张额度卡、项目概览和页脚
4. 全局页面无滚动溢出，只有项目表等内部容器允许滚动
