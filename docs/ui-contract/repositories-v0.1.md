# Codex Companion 代码仓库页 UI Contract（v0.1）

- 创建时间：2026-06-04
- 页面来源：`docs/page-design-spec-v0.3.md` 第 4 节
- 对应版本基线：`v0.2.2-dev.62`
- 当前状态：设计确认稿，供第三页出图与后续实现使用

## 1. 页面目标

代码仓库页不是总览页的项目表放大版，也不是 GitHub 仓库看板。

首屏必须优先回答：

- 当前扫描目录下，哪些本地 Git 仓库最近最活跃？
- 选中的仓库最近改了什么，工作区是否仍有未提交改动？
- Codex 本地会话最近主要落在哪些仓库，并对应了多少累计 Token 与 API 等价成本，但不把这些投入字段做成首屏主卡？

## 2. 修正原则

第三页沿用前两页已经确认过的修正方法：

- 先对齐真实数据边界，再定页面字段，不为设计图补伪数据。
- 壳层直接复用第一页真实截图，不再参考旧版三页初稿里各自漂移的壳层。
- 页面主对象统一为 **本地 Git 仓库**，不把本地目录、GitHub 远端和仓库标签混成同一级概念。
- 保留顶部筛选和左中右联动结构，但不把 `归因 Token` 与 `API 成本` 做成首屏四卡；它们只作为中部工作台的仓库级下钻信息出现。
- 不再使用“仓库排行”命名；左侧是可排序的仓库详情表，不强调固定榜单语义。
- 扫描目录和远端地址只承担数据溯源与识别作用，不再占据页面主视觉。
- 参考 `dev-ledger` 的 Git 页做法：仓库列表和当前仓库详情可以出现 `Token / 成本`，但应保持紧凑，避免把第三页重新做成账本页。
- `最近提交` 只保留“仓库新鲜度证明”和上下文提示功能，不再占据顶部主卡，也不再在详情里用长列表抢主视觉。

## 3. 壳层基准

第三页壳层必须直接复用第一页当前已落地截图：

- `local_dev_work/overview-1360x900-dev53.png`
- `local_dev_work/overview-billing-1360x900-dev53.png`

必须保持一致：

- 左侧品牌区、状态文案和底部设置入口
- 主导航标签与图标
- 顶部标题 + 副标题 inline 结构
- 顶部右侧 `状态 / 刷新 / 快照`
- 卡片圆角、描边、阴影、留白密度和整体蓝白基调

## 4. 数据边界

当前第三页只允许依赖现有采集链路稳定提供的字段：

- 仓库标识：`name`、`path`
- Git 元数据：`defaultBranch`、`remoteUrl`
- 活动聚合：`today / sevenDays / month / workingTree`
- Codex 投入：`tokens.total`、`apiCostUsd`
- 会话关系：`sessionCount`、`lastCodexAt`
- 提交列表：`recentCommits`

当前页面明确不做：

- GitHub PR、Issue、Actions、Stars、forks 等云端元数据
- 语言占比环图、文件体量图、仓库风险等级这类旧稿字段
- 以 `归因 Token`、`API 等价成本` 作为第三页首屏核心主卡
- 伪造 `30 天成本`、`30 天 Token` 等当前合同还未提供的仓库级周期字段

## 5. 页面结构

### 5.1 第一行：筛选与范围

保留顶部“按仓库分类”的视觉形式，但语义统一成 **扫描目录筛选**：

- 搜索框：`筛选 Git 仓库`
- 目录 chips：`全部 + 各扫描目录`
- chips 只承担过滤作用，不承担排名和状态解释

约束：

- 目录 chips 对应当前配置的仓库扫描根目录。
- 如果后续需要显示每个目录下仓库数，只能基于当前已扫描结果计算，不能请求云端或附加索引。

### 5.2 第二行：顶部四卡

固定四张卡：

- `今日改动`
- `近 7 日改动`
- `本月改动`
- `关联仓库`

约束：

- 复用第一页当前四卡的比例、状态徽标位置和图标语言。
- 第四卡建议显示存在 Codex 会话归因的仓库数，而不是全局最近一次提交时间。
- 顶部严禁出现 `归因 Token`、`文件体量`、`API 等价成本`。

### 5.3 第三行：左侧仓库详情表

左侧卡标题建议用 `Git 仓库详情`。

字段固定为：

- 仓库
- 今日改动
- 近 7 日改动
- 本月改动
- Codex 投入
- 最近提交

约束：

- 去掉旧稿中的 `#` 排名列。
- 不再放一排排序 chips 或按钮。
- 默认按 `最近提交` 倒序排列。
- 点击表头字段即可切换排序；再次点击同一字段时在正序 / 倒序之间切换。
- 允许点击排序的字段为：`今日改动 / 近 7 日改动 / 本月改动 / Codex 投入 / 最近提交`。
- 默认分支折叠进仓库名下方的辅助信息，与路径一起显示，不额外占列。
- `Codex 投入` 列主值显示累计 Token，辅值显示 API 等价成本。
- 不显示 `文件体量`、`风险等级`。

### 5.4 第三行：右侧已选仓库

右侧卡标题建议用 `已选仓库`。

必须包含：

- 头部信息：仓库名、完整路径、默认分支、最近提交时间
- 四个指标块：`今日改动 / 近 7 日改动 / 本月改动 / 工作区改动`
- `Codex 投入概览`：`累计 Token / 累计 API 等价成本 / 关联会话 / 最近 Codex 活动`
- 最近提交只保留最新 `2` 到 `3` 条，或退化成“最近一次提交 + 查看全部”
- 仓库状态：`origin 地址`

约束：

- `origin` 地址只作为识别信息的一行文案，不单独做大卡。
- 没有远端时显示 `未配置远端`。
- 不再展示语言分布或文件体量图。
- 当前数据边界下，Token 和成本统一使用累计口径，不补虚构周期字段。
- `Codex 投入概览` 应做成独立的小分区或 `2 x 2` 指标矩阵，不应生硬地挤成一条长横排。

### 5.5 第四行：紧凑页脚说明

页脚只保留紧凑说明，不再放单独“大块数据源根目录”卡：

- 数据来源：`Codex 本地 sessions、archived_sessions、本地 Git`
- 扫描目录数量或目录 chips
- 仓库总数
- 明确说明：不读取 GitHub 云端元数据

## 6. 交互约束

- 左侧选中某个仓库后，右侧详情必须同步切换。
- 搜索和扫描目录筛选只改变当前列表与右侧可选范围，不改变页面布局。
- 没有命中仓库时，左侧显示空状态，右侧显示“请选择仓库”占位，不允许用伪示例数据填充。

## 7. 后续实施顺序

1. 先复用第一页壳层与页脚说明结构。
2. 再实现搜索框、扫描目录筛选和左侧排序表。
3. 然后补齐右侧单仓库详情与提交列表联动。
4. 最后再做第三页真实 Electron 截图验收，至少覆盖 `1360 x 900` 与 `1080 x 720`。
