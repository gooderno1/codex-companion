## 1. 官方证据与可以确认的边界

核对时间为 2026-09-17。官方网页会变化，以下结论需要连同来源日期保存。

| 问题 | 结论 | 来源 |
| --- | --- | --- |
| 套餐是否按总 Token 条数扣额度 | 不能确认；模型、上下文、缓存、推理、工具和运行方式都会影响消耗 | [Pricing](https://learn.chatgpt.com/docs/pricing) |
| 是否公开固定月度 Token / 美元预算 | 本次查阅未找到；月付是订阅账期，公开窗口说明以 5 小时、周为主。具体账户以接口的 windowDurationMins 为准 | 同上 |
| 是否存在按 Token 加权的计费依据 | 额外 credits / credit-based 计划公开了模型级输入、缓存和输出单价，但没有公开“包含额度百分比→固定 credit 总量”的完整公式 | 同上 |
| Fast 是否影响套餐额度 | 是；GPT-6 / GPT-5.6 / GPT-5.5 的 Codex Fast 为标准 credit 的 2.5 倍，GPT-5.4 为 2 倍。API Priority 是另一价格体系，不能套用 Codex 倍率 | [Speed](https://learn.chatgpt.com/docs/agent-configuration/speed) |
| 是否只统计本机就能还原账户扣额 | 不能；ChatGPT Work、云端、其他设备及其他共用功能可能消耗同一池 | [Pricing](https://learn.chatgpt.com/docs/pricing) |
| 为什么价格可能变化 | 价格和促销本身有时间属性；例如当前 Sol 标准价格声明优惠至少持续到 2026-11-21，这不等于届时必然变价 | [Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol) |
| 能否用 /v1/models 自动取得价格 | 当前公开响应只有模型身份、创建时间、所属方、停用日期等，没有价格字段 | [List models](https://developers.openai.com/api/reference/resources/models/methods/list) |

API 标价不是 OpenAI 的内部推理成本，也不是用户套餐实付。研究可以建立“本机可见工作量相当于多少 API 标价”的估计，不能据此宣称发现官方预算或真实利润率。

## 2. 先拆成四种指标

1. **官方当前余量**：继续读取当前账户对应额度池，不以本研究估计覆盖圆环或低额度提醒。
2. **本月已记录 API 等价成本**：按事件时间求和，表示本机工作量；完整价格覆盖也不代表覆盖全部账户活动。
3. **窗口满额等价值（估计）**：在同一个额度池和稳定规则片段内，用已用百分比变化对齐本机等价成本增量。
4. **按周尺度标准化的月度参考值（可选）**：将已估出的时变周容量按覆盖天数折算，只用于跨时期比较，不叫官方月额度；没有观测的时段保持空缺。

必须同时区分：自然月 / 用户账期 / 官方周窗口 / 手动重置后片段 / 检测到的规则变点。跨月窗口不能整体划给首次活动月。

## 3. 成本计算与历史价格

基础公式（每百万 Token 单价）：

`C = ((I - R - W) × P_input + R × P_cache_read + W × P_cache_write + O × P_output) / 1,000,000`

- `I` 为总输入；`R` 为已包含在输入里的缓存读取；`W` 为已包含在输入里的缓存写入；`O` 为总输出。
- 缓存写入按它自己的费率替代普通输入，不能在全部普通输入计价后再加一整份写入费。官方依据：[Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)。
- 推理 Token 已包含在输出中，不能再次相加。
- 校验 `R + W <= I`、`reasoning <= O`；字段未知和明确 0 分开保存，不静默修正损坏数据。
- 将 API USD 和 Codex credits 分为两张费率表，两套服务档位；不能一律以 25 credits = 1 USD 反算所有模型 / 档位 / 合约。
- 长上下文必须按官方规定的“单请求 / 整会话”计价范围应用阈值，不能对会话累计输入是否超过 272K 做统一判断。GPT-6 / GPT-5.6 页面写 full request，GPT-5.4 页面写 full session，应保留来源差异。
- 缺少历史服务档位时只输出标准档重估；可附情景范围，但不能自行认定用户一直开 / 关 Fast。
- 工具、图片、语音和单独计费项目只有取得对应结构化用量和明确费率时才纳入，不能从对话文字猜数量。
- 未知模型保持 `unpriced`，金额不是 0；合计显示“已知部分”，同时展示未定价事件数与 Token 比例。

历史表提供两个视图：

- **按当时价格**：仅使用有可靠 effectiveFrom 的费率；缺失历史价格时明确空缺，保留部分合计。
- **按所选价格快照重估**：固定一套价格比较几个月的工作量；明确标注价格快照日期，不能当作当月实付或当时标价。

本轮个人月表采用第二种，即 2026-09-17 标准档价格重估；没有把今天新查到的价格伪装为历史生效价。

## 4. 窗口容量估计

对同一账户、同一 `limitId`、相同 `windowDurationMins`、同一重置片段，选取两个观测点 a / b：

`Δp = usedPercent_b - usedPercent_a`（单位：百分点）

`ΔC = sum(cost of local events in (a, b])`

`B = 100 × ΔC / Δp`

合成样例：已用从 20% 到 40%，对齐成本增量为 $60，则该片段满额等价值为 $300。若另一个片段得到 $450，应记录为另一片段估计，不能强行月内平均成固定预算。

### 本轮可复现实验

- 复用已有采集器计算 Token 增量，研究脚本不改写 session、数据库或应用缓存。
- 主池只取 `codex`；早期缺少 limitId 的记录标记 legacy，不与 Spark 的独立额度池混合。
- 按 `windowDurationMins=10080` 找周窗口，不能假定周额度永远在 secondary；按 resetsAt 分组，最多允许相对锚点 120 秒的时钟舍入差。
- 排除窗口有效时间之外、缺失比例、无有效重置时间和达到 99% / 100% 截顶的观测。
- 使用共享核心已确认的 reset 边界排除跨边界区间，并剔除已被新窗口替代的旧窗口迟到观测；边界检测数不等于用户兑换重置次数。
- 同一 5 分钟桶取比例与时间中位数，减少并发会话重复上报的影响；同边界回落超过 3 个百分点先切片，小幅回退样本不用于拟合。
- 每累计至少 10 个百分点形成不重叠样本区间；区间不超过 48 小时，主池相关未知模型 Token 不超过 2%，成本必须大于 0。
- 片段点估计为 `100 × sum(ΔC) / sum(Δp)`；记录样本数、百分点跨度、区间分布、覆盖情况和异常标记。
- 比较 5 / 10 / 15 个百分点阈值、1 / 5 分钟桶及事件时间 ±2 分钟偏移。P10–P90 是样本离散区间，不是假装为 80% 置信区间。
- 用上一段换算系数预测下一段已用比例，对比 API 加权和原始 Token 方法，避免只展示拟合内相关性。
- 个人结果和可复现脚本保留在 `local_dev_work/quota-research-2026-09-17/`，不上传个人使用账本。该实验是方案验证，不替代正式 reset engine。

### 生产方案中的质量门槛（初始建议，待回测定标）

- 至少 3 段、累计至少 30 个百分点后显示中等证据估计；1–2 段只显示探索性点，不能显示“稳定容量”。
- 价格覆盖以字段和 Token 双重检查；98% Token 覆盖不等于 98% 成本覆盖，昂贵未知模型应直接降级。
- 对强离群值使用 Huber 回归或加权中位数；保存被剔除样本及原因。正式误差区间按日 / 会话簇 bootstrap，避免把并发重复观测当独立样本。
- 切换账户 / 套餐 / 价格版本 / 服务档位、手动 reset、自然窗口、采样中断和显著回落都建立边界，不跨边界平滑。
- 官方值回落也可能是返还、策略变化或迟到观测；用共享核心确认 reset，不能只靠差分给它贴“赠送重置”标签。
- 比例只以整数上报时，两个端点可能带来约 1–2 个百分点的差分不确定性。1% 的小区间不适合除法放大。
- 缺少另一设备 / 云端消耗通常令本地成本比值偏低；误计入其他额度池、错误模型、重放或档位差异也可能使估计偏高。因此不把 B 当严格上下界。
- 若缺少账号来源和稳定档位，只能标为“在这批本地记录上的有效 API 等价值”，不能因接口 planType 名称自行推断订阅价格。

## 5. 随时间变化与月度汇总

- 容量函数记作 `B(t)`，价格函数记作 `P(model, tier, effective_time)`，必须分开。价格变动、模型组合变动与套餐政策变动不是同一回事。
- 先沿自然窗口与已确认 reset 分段，再监测片段内变点。候选规则：连续 3 个合格区间的稳健中位数相对上一段偏移超过 20%，且明显超过重采样 / 对齐误差后提示“换算关系变化”；20% 是待校准的产品阈值，不是官方规则。
- 不能仅凭模型切换后的价格差异断言官方缩减预算。需要同模型 / 同档位匹配、外部用量排除和后续区间验证，才能提升证据等级。
- 月度已用成本直接按本地时区事件日期求和，不用“本月用了 200% × 最近一周的满额值”。
- 月度参考容量若确需提供，采用 `sum(B_s × overlapDays(s, month) / 7)`，显示观测覆盖天数；未观测时段不外推，不把片段样本区间误当全月有效区间。
- 手动 reset 单列“新发放”“被替代未用额度”“已实际消耗”。例如同容量 B 下在已用 60% 时全重置，发放 B、替代未用 0.4B，净增加 0.6B；不要重复把两个满额窗口都当自然周配额。
- 同时存在 5H 与周限制时，实际可用程度还受较短窗口约束；30 天按周尺度折算只能用于比较，不是承诺用户一定能用完的月预算。
- 月度账本优先交付已用成本、窗口估值分布和变化时间；“月度容量”放在高级说明中，默认不显示一个伪精确总额。

## 6. 产品落点与交互

### Codex 账本 → 额度估算详情

- 保持主余量卡官方当前口径，新增“额度估算”入口。
- 顶部固定显示：账户 / 套餐来源、额度池、范围、价格口径、最近更新时间、已知定价覆盖。
- 两个视图：“按月已用成本”“按窗口估值”。月表支持 Token / 金额排序，展开月后看模型和每日明细。
- 月表列：月份、原始 Token、标准等价成本 / 已知部分、未定价模型、记录活跃日、账单或自然月说明。无记录月份显示“无本地记录”，不能显示免费使用。
- 窗口图以阶梯片段展示 B(t)，标注自然边界、reset、模型 / 档位变化和价格版本变化；不以连续平滑曲线暗示未观测值。
- 窗口表列：开始 / 结束、官方已用范围、对齐成本、估计满额价值、样本区间、证据等级、重置情况。
- 点击估值看计算明细：Δp、ΔC、有效样本数、纳入 / 排除理由、价格来源和服务档位覆盖；保留原始 Token 数，方便复核。
- “成本走势变化”与“套餐规则疑似变化”用不同文案；后者默认弱提示，不发低额度通知。

### 设置 → 模型价格

- 显示目录版本、官方核对时间、生效时间是否已知、来源、更新状态及未定价模型。
- 提供立即检查、自动更新开关、离线目录、更新历史和版本回退；应用价格变化后明确提示哪些历史视图被重估。
- 未知模型仍可正常累计 Token；价格数据补齐后重估对应模型，用户不必升级整个应用。
- UI 使用“标准 API 等价成本”“估算区间”“本机可见记录”，避免“实际账单”“官方月度预算”等超出证据的标签。

## 7. 新模型计费自动更新

### 推荐架构

`官方公开文档 → 定时采集 / 差异检查 → 结构化价格目录 → 校验与审批规则 → 版本化发布 → 客户端定时更新 → 派生成本重估`

- 不让每个客户端各自解析网页；网页结构变动会使用户得到不同结果，也无法稳定还原历史价格。
- 维护公开、版本化、只含价格的 JSON 目录，可先依托本项目的 GitHub 数据资产发布。目录包需要独立版本，与应用版本解耦。
- 发布端建议每 6 小时检测官方模型页、Pricing 与 Speed 的变化；客户端建议每天一次，提供手动刷新。这里是方案，不在本轮创建定时任务。
- 未知模型触发对完整目录的有节流刷新，不上传本机模型清单、Token、账户信息、项目或会话信息。
- 定价来源页的来源 URL、抓取时间、内容哈希和必要证据片段保留用于审计；不同官方来源冲突时暂停自动启用冲突条目。
- 自动接纳的边界：现有解析 schema 内的新标准模型 / 纯数值变化，在字段完整、来源交叉一致、别名明确和测试通过后自动生成候选；初期新模型需要维护者审核一次，客户端随后自动获得。
- 未见过的计费维度、长上下文规则、促销生效时间、异常跳变或模糊别名必须进入待核对状态；不是把没查到的字段当 0 或沿用相似模型。
- “全自动采集”和“自动启用所有推断价格”应分开。后续成熟解析器可扩大自动启用范围，但保留隔离和回退。

### 目录必要字段

- `schemaVersion / catalogVersion / publishedAt / verifiedAt / effectiveFrom / effectiveTo / sourceHash`。
- `modelId / aliases / modality / billingSystem(API USD, Codex credits) / serviceTier / region / currency / perTokens`。
- `input / cacheRead / cacheWrite / output`；明确未知值为 null，不用 0 表示未知。
- `longContextThreshold / pricingScope(request, session) / inputMultiplier / cacheMultiplier / outputMultiplier`。
- `promotion`、`effectiveTimeBasis(official, first-observed, unknown)`、`sources[]`、`status(verified, pending, retired)`。
- 模型发布日期不自动等于价格生效日；首次发现日期不覆盖历史生效日期。修订旧价格保留 revision 和修订理由。
- 别名必须有官方证据；日期快照仅匹配已登记模型，禁止把所有 gpt-6-* 都匹配到 Astra。

### 客户端可靠性

- 内置已知版本作为离线回退，网络失败继续使用最后验证目录并显示陈旧状态。
- 固定 HTTPS 来源、schema 校验、大小限制、单调版本、防止重放与可验证内容签名；签名数据不包含可执行代码。这与 Windows 安装包 Authenticode 签名是不同机制。
- 原子更新目录，先生成新的派生估值，再切换显示；旧版本仍可用于固定快照和审计。
- 遵循现有网络 / 隐私偏好。自动价格目录下载的开关和公开隐私说明需在实施时同步，不默认扩展上传行为。

## 8. 数据与代码改造顺序

1. **价格目录与重估基础**：将 `src/main/collectors/pricing.ts` 的硬编码费率拆为纯计算器和版本化目录；API / credits 结果均带 pricingStatus 与版本，保留准确别名。
2. **原始用量与派生成本分离**：当前 session cache / SQLite events 存有派生成本，定价变化会迫使索引失效。改为保存原始计数与元数据，派生成本按 `(eventId, catalogVersion, mode)` 缓存；聚合按 `(model, tier, date, pricingRule)` 加速。
3. **补齐解析契约**：以共享核心优先方式补入请求计数、cacheWrite、modelSnapshot、tier / unknown、account scope、计数重置 / 压缩标记；缺失字段不得回填成已知标准档。共享逻辑先发核心正式包或远程 tag，再升级 Companion。
4. **额度观测表**：独立持久化观察时间、官方来源、池、duration、resetAt、usedPercent、匿名本地账号键、planType、观测延迟和 reset 证据；不依赖每次扫描 JSONL 才重建时间序列。
5. **月表与重估交付**：先给出能核实的已记录成本；支持固定价格快照和部分定价标签。
6. **窗口拟合与变化提示**：后台查询后增量计算，索引为 `(accountKey, limitId, duration, observedAt)`；UI 只接收汇总及证据摘要，详情异步加载。
7. **自动价格目录分发**：在完整回归、签名和缓存迁移后上线，价格更新不重读全部会话文件、不阻塞界面。
