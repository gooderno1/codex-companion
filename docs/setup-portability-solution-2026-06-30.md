# 安装后数据接线与跨设备可用性解决方案

- 创建时间：2026-06-30
- 创建时版本基线：`v0.3.0`
- 需求主题：解决应用安装后过度依赖当前开发者本机 Codex 数据和路径的问题，让新电脑、新用户能明确完成数据接线
- 影响页面：设置页、总览页数据源状态、代码仓库页数据来源、README、打包配置
- 关键设计约束：本项目仍保持 Codex 专用、非官方声明、本机读取、无上传；不读取云端账号；不把开发者本机路径或配置打进安装包；用户必须能看到和修改本机数据源路径
- 相关数据源：Codex home、`sessions`、`archived_sessions`、Git 仓库根目录、Electron `userData/settings.json`

## 1. 问题判断

当前 `v0.3.0` 在开发者机器上安装后能直接显示 Codex 信息，是因为：

- 默认 Codex home 为 `CODEX_HOME || ~/.codex`，开发者机器刚好有可解析历史数据。
- 仓库根目录会自动发现常见目录，开发者机器刚好命中本地项目目录。
- Electron `userData` 中可能已有开发和内测期间保存过的设置、快照和缓存。

这些行为本身不是隐私泄露：安装包没有携带开发者的原始 Codex session 或 Electron `userData`。真正的问题是产品体验缺少“首次接线流程”，导致换电脑后用户只看到空状态或开发机式默认值，却不知道下一步应该配置什么。

## 2. 解决目标

1. Codex 数据目录必须可见、可改、可恢复默认。
2. Git 仓库根目录必须可见、可改、可恢复默认。
3. 保存任一数据源配置后必须立即刷新，用户能马上验证是否接通。
4. 空状态要明确指向 `设置`，而不是让用户误以为应用坏了。
5. 后续 Windows 分发只保留安装版，减少“便携版 / 安装版”选择成本。
6. README 必须说明新电脑首次配置方法和数据不会随安装包分发。

## 3. 本轮实施方案

### 3.1 Codex home 配置

- 在 `AppPreferences` 中新增 `codexHome`。
- `SettingsStore` 默认使用 `CODEX_HOME` 环境变量；没有时使用 `~/.codex`。
- 设置页新增 `Codex 数据目录` 区块：
  - 显示当前路径。
  - 支持手动输入。
  - 支持系统目录选择。
  - 支持恢复默认路径。
  - 保存后立即刷新仪表板。

### 3.2 Git 仓库根目录配置

- 保留已实现的手动输入、选择目录、移除、保存并刷新。
- 补充恢复默认路径能力，方便用户从错误配置回到系统自动发现。

### 3.3 数据采集接线

- `collectCodexData` 不再只从进程环境推断 Codex home。
- 主流程从 `preferences.codexHome` 传入当前用户配置。
- `sourceHealth.codexHome` 继续展示实际采集路径，方便排障。

### 3.4 打包策略

- `package:win` 后续只构建 NSIS 安装版。
- `build.win.target` 只保留 `nsis`。
- 继续保留当前未签名、默认 Electron 图标的内测边界，公开发布前再处理签名和图标。

## 4. 本轮不处理

- 不引入云端登录或账号授权。
- 不自动扫描整盘查找 `.codex`，避免慢扫描和隐私边界扩大。
- 不上传诊断信息。
- 不实现自动更新。
- 不重新发布 `v0.3.0`，本轮作为 `v0.3.1-dev.2` 开发修复进入后续版本。

## 5. 验证路径

- `npm run build`
- `git diff --check`
- Electron 设置页截图检查：
  - 能看到 `Codex 数据目录`。
  - 能看到 `仓库根目录`。
  - 两类路径都不溢出。
  - 保存、选择目录、恢复默认等按钮不重叠。

## 6. 后续建议

1. 增加真正的首次启动向导，把 Codex home、仓库根目录和隐私边界放在第一屏完成。
2. 增加“复制脱敏诊断摘要”，只导出路径是否存在、文件计数、刷新状态和版本号，不导出原始内容。
3. 增加“打开数据目录”和“打开设置文件”按钮，方便内测排障。
4. 给公开版补应用图标和代码签名。
